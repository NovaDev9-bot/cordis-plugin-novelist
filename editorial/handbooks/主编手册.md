# 主编手册（V3-P3 · 2026-09-05）

> 按需检索注入，不进 persona 长文。消费方=主编。

## 一、分档判据与处置

| 档 | 定义 | 处置 |
|---|---|---|
| P0 | 吃书/断裂/弃书风险（语义级：情节/人设/伏笔/结构） | 必改；回改后重新派试读（A-B 冷读门走 protocols/A-B冷读协议.md） |
| P1 | 体验缺陷（不出戏但伤读感） | 攒批进修订批，一次改完 |
| P2 | 润色（文字级） | 校对批处理；纯 P2 改动免重试读（主编裁定注理由） |

## 二、评分口径（何时用哪档仪器）

- **每章轻量门三查**（与试读合并一次调用，二元问题）：钩子在不在（章末）/承诺兑没兑（前文埋的当收）/事实对不对账（前情事实卡）。
- **检查点章全量评分卡**（卷首尾/大转折）：六维行为锚定+证据引用+z 三档+成对判（细则=protocols/责编评分卡-番茄.md v2）。判词一律 novel_score 落盘（判据账），禁只写 markdown 不落账。
- **仪器定位**：飞行模拟器非裁判——z 在市场相关验证（n≥60 且 ρ≥0.3）前**永不卡章**，只作参考+升级触发。

## 三、事件带处置（细则=protocols/事件带协议.md）

- 落带时机：每章 decision（章纲/调度取舍，why 必填）；判词与回改处置 verdict/revision 随状态流转；自设欠线 open_thread 必带 closes 预期章；闭线用 closes_thread 对账。
- **压缩触发前**：当轮推理摘要 kind=checkpoint 落带（抗压缩记忆）。
- **批级断点续跑 SOP**：中断恢复=查 status.json 最后已定稿章 → novel_event read 带尾 → 重建调度位 → 从下一章 outline 起。50 万字长批必须可续（断供/收束事故皆有前科）。

## 四、派工与熔断

- **主笔=同事线**（continuable 后台 spawn；2 分钟无回信即降级一次性前台 spawn 并留痕）；**试读/校准/校对=永远一次性前台 spawn**（盲读隔离与账本写入口安全，不进同事线）；**档案员=按需 one-shot**（R1 后账本自动派生，降格）。
  〔2026-09-18 修订〕原句写"策划/档案员=同事线"——**策划这一座位自 v7.2（ADR-036 两座位制）起已并入主笔**，常驻同事线只剩主笔。真源＝`lib/novelist.js` guide 的「派工分工」行。
- 同任务连续 2 次零交付=熔断，主编自审替代+留痕+挂事项板复盘。
