#### 2.4 长篇章节续写流程（第2章及以后）

**触发条件**：用户提出"下一章"、"续写第X章"、"第X章"等需求（X≥2）

**⚠️ 重要说明**：本流程为长篇小说第2章及以后章节的续写流程，包含上下文管理、创作、输出、后续处理四个阶段。

**阶段一：续写前上下文管理（强制执行）**

**⚠️ 硬规定：续写前强制检查（自动补齐模式）**

**检查项1：大纲文件存在性检查**
- **检查操作**：确认 `novel-creation-evo-output/[小说标题]_大纲.md`〔模板〕〔仓外〕 文件存在
- **如不存在**：**自动创建基础大纲文件**，包含：主题立意（待用户补充）、三幕式结构框架、人物设定模板、伏笔规划表。创建后提示用户："大纲文件已自动创建，请补充核心设定后继续。"
- **如存在但未读取**：**必须执行**下方"步骤1：强制读取初始大纲"

**检查项2：追踪文件存在性检查**
- **检查操作**：确认 `novel-creation-evo-output/[小说标题]_追踪.md`〔模板〕〔仓外〕 文件存在
- **如不存在**：**自动创建追踪文件**，根据大纲内容初始化：章节进度表（全部标记为"未开始"）、人物状态表（提取大纲人物设定）、伏笔状态表（提取大纲伏笔规划）。创建后提示用户："追踪文件已自动创建并初始化。"
- **如存在但未读取**：**必须执行**下方"步骤2：强制读取追踪文件"

**检查项3：已创作章节文件存在性检查**
- **检查操作**：确认 `novel-creation-evo-output/[小说标题]_第X章.md`〔模板〕〔仓外〕（X从1到最新章）文件存在
- **如第1章不存在**：**自动创建第1章占位文件**，包含：章节标题（待填）、场景设定（待填）、核心事件（待填）。创建后提示用户："第1章占位已创建，建议补充内容或继续当前章节创作。"
- **如中间章节缺失**（如已创作到第5章但缺少第3章）：**自动创建缺失章节占位文件**，包含基础结构（标题、场景、核心事件待填）。提示用户："第X章占位已创建，建议补充内容或继续当前章节创作。"
- **如存在但未读取**：**必须执行**下方"步骤3：逐章强制读取所有已创作章节"

**检查项4：读取状态确认（创作前必须输出）**
```
📋 第X章续写前强制检查
□ 大纲文件：已读取 / 未存在（已自动创建）
□ 追踪文件：已读取 / 未存在（已自动创建）  
□ 已创作章节：已读取 / 未存在（已自动创建占位）
□ 检查结论：✅通过 / ⚠️已自动补齐
```
- **如任一项为"不存在"**：**自动创建/补齐**，继续创作流程，不中断
- **如任一项为"未读取"**：**禁止进入阶段二**，必须返回执行读取流程
- **全部显示"已读取"或"已自动创建"**：允许进入阶段二正文创作

---

**⚠️ 强制上下文记忆要求**：当用户输入包含"下一章"、"开始"、"继续"、"第X章"、"续写第X章"等明确表示继续创作后续章节的指令时，**必须**执行以下上下文管理流程：

**步骤1：立即强制自动读取初始大纲**（完整读取，不可跳过）：
- **批量读取指令**：**必须**一次性读取 `novel-creation-evo-output/[小说标题]_大纲.md`〔模板〕〔仓外〕 文件
- 主题立意、世界观设定
- 三幕式结构规划（各幕章节区间）
- 情节团划分（低/中/高危机区间及关键事件）
- 人物设定（主角成长弧光、盟友关系、反派动机）
- **核心：所有伏笔规划**（埋设位置、回收章节、未回收伏笔清单）

**步骤2：立即强制自动读取追踪文件**（完整读取，不可跳过）：
- **批量读取指令**：**必须**一次性读取 `novel-creation-evo-output/[小说标题]_追踪.md`〔模板〕〔仓外〕 文件
- 获取最新的人物状态（位置、关系、能力）
- 获取未回收伏笔清单（紧急程度、计划回收章节）
- 获取上一章结尾悬念状态
- 确认追踪文件中的"当前完成章节数"与"章节完成标记"

**步骤3：立即逐章强制自动读取所有已创作章节**（必须执行）：

**正确做法（强制执行）**：
1. **必须使用read_file工具逐章读取**：对每一章文件调用read_file工具，**严禁跳过**
2. **读取顺序**：第1章 → 第2章 → ... → 最新章，**必须按顺序逐个读取**
3. **读取范围**：**必须读取从第1章到最新章的所有章节**，不能只读最近2-3章
4. **严禁基于记忆**：即使"记得"前面内容，也必须重新读取文件，**对话历史记忆不可靠**

**操作步骤**：
```
对于第1章到最新章的每一个文件：
  1. 调用 read_file(file_path="novel-creation-evo-output/[小说标题]_第X章.md")
  2. 确认文件内容已完整读取（不是只读文件名）
  3. 提取关键信息：本章事件、人物状态变化、新埋设的伏笔、回收的伏笔、结尾悬念
  4. 记录到内部上下文，供后续章节参考
```

**内部读取验证（证明真的读了）**：
- 读取完成后，必须能回答：第1章的核心事件是什么？主角初始状态是什么？
- 必须能回答：上一章结尾的具体悬念内容（不是概括，是原文细节）
- 必须能回答：当前未回收的伏笔有哪些？分别是在哪一章埋设的？
- **如果不能回答，说明没读，必须重新读**

**重点关注**：
- 已埋设但未回收的伏笔（必须追踪状态）
- 人物关系演变过程
- 情节发展轨迹
- 悬念设置与解答情况

**严禁（违者严肃处理）**：
- ❌ **严禁"声称读取"但实际未调用read_file工具**：这是欺骗行为
- ❌ **严禁只读最近2-3章**：必须读第1章（原始设定）+所有中间章节（发展脉络）+最新章（直接承接）
- ❌ **严禁仅依赖对话上下文记忆**：必须再每一章创作前读取大纲+追踪+所有章节文件
- ❌ **严禁只读文件名或文件列表**：必须读取文件**内容**
- ❌ **严禁基于大纲概要猜测章节内容**：大纲是规划，章节是实际内容，两者可能不同

**步骤4：强制文件读取检查**（核心修复：确保真的读了文件）：

**读取确认要求（必须在创作前输出）**：
```
📋 文件读取确认
✅ 已读取大纲文件：novel-creation-evo-output/[小说标题]_大纲.md
   - 主题立意：[复述大纲中的主题，证明真的读了]
   - 总章节数：[X章]
✅ 已读取追踪文件：novel-creation-evo-output/[小说标题]_追踪.md
   - 当前完成章节数：[X章]
   - 最新人物状态：[复述关键状态，证明真的读了]
✅ 已逐章读取章节文件（必须能复述每章核心内容）：
   - 第1章：novel-creation-evo-output/[小说标题]_第1章.md
     核心事件：[复述第1章具体发生了什么，不是概括]
     结尾悬念：[复述第1章结尾的原话或细节]
   - 第2章：novel-creation-evo-output/[小说标题]_第2章.md
     核心事件：[复述第2章具体发生了什么]
     结尾悬念：[复述第2章结尾的原话或细节]
   - ...（中间章节同样要求）
   - 第X章（最新）：novel-creation-evo-output/[小说标题]_第X章.md
     核心事件：[复述最新章具体发生了什么]
     结尾悬念：[复述最新章结尾的原话或细节]
✅ 数量核对：追踪文件记录[X章] = 实际读取[X章]
✅ 第1章原始设定已掌握：[复述世界观、主角初始状态等关键设定]
✅ 未回收伏笔已清单化：[列出所有未回收伏笔及埋设章节]
```

**读取验证标准（无法复述=没读）**：
- 必须能**复述**第1章的核心事件（是具体内容，不是"主角开始了冒险"这种概括）
- 必须能**复述**上一章结尾的具体悬念（是原文细节，不是"留下悬念"这种空话）
- 必须能**列出**所有未回收伏笔及埋设章节
- **如果无法复述，说明没读，必须返回重新读取**

**步骤5：读取长篇创作规范**（字数、结构、悬念机制、引导句格式、伏笔管理）

**步骤6：验证与规划**：
- **验证伏笔回收状态**：列出所有未回收伏笔，明确本章需要回收/埋设的伏笔
- **验证人物关系一致性**：确认主角/配角当前状态、关系网变化
- **验证情节连贯性**：确保本章情节在整体大纲中的位置正确
- **⚠️ 验证情节推进规划（关键新增）**：
  - 明确本章的"核心推进事件"（必须能用1句话清晰描述）
  - 确认本章结束时主角的状态变化（认知/目标/处境/关系至少一项必须有变化）
  - 检查本章是否为"可删除章节"（如果删除本章主线仍然连贯，则必须重新规划）
  - **强制要求**：在创作前必须明确"本章推动主线向结局靠近的具体方式"

**步骤7：回答必问问题**：
1. 当前是第几章？总共有几章？（从大纲读取）
2. 当前章节属于哪个情节团？该情节团的核心任务是什么？（从大纲读取）
3. 上一章结尾是什么悬念？如何承接？（从所有前文确认）
4. 本章需要回收哪些旧伏笔？（从伏笔规划读取）
5. 本章需要埋设哪些新伏笔？（从大纲规划）
6. 本章的人物关系有什么变化？（从大纲规划+前文演变确认）
7. 本章的情绪爽点在哪里？（从大纲规划）
8. **⚠️ 本章的核心推进事件是什么？**（关键新增）
   - 必须能用1句话清晰说出"本章发生了什么推动主线的关键新事件"
   - 必须是"首次发生"而非"重复已知信息"
   - 必须是"情节推进"而非"原地踏步"
   - **禁止回答**："主角继续调查"、"主角思考现状"、"主角回忆过去"（这些都是原地踏步）
   - **正确示例**："主角发现地下室的秘密入口"、"主角与反派首次正面冲突"、"主角得知自己身世的真相"
9. **⚠️ 本章结束时主角状态与章首相比有何变化？**（关键新增）
   - 认知变化：主角知道了什么新信息？
   - 目标变化：主角的行动目标是否调整？
   - 处境变化：处境是更好还是更糟？
   - 关系变化：与关键人物的关系是否有实质改变？
   - **验证标准**：如果删除本章，主角的状态会和现在一样吗？如果是，说明本章缺乏推进价值

**⚠️ 强制隔离规则（章节创作严格执行）**：
- **严禁引入示例元素**：续写章节时，**绝对禁止**引入电梯、快递、门锁、红衣女子、神秘保安等内部示例中的任何元素
- **严格遵循大纲**：所有情节、人物、场景必须基于初始大纲和已创作章节延续，**严禁套用示例情节结构**
- **伏笔回收原创**：回收伏笔的方式必须基于大纲规划，**严禁使用示例中的伏笔回收套路**

**⚠️ 关键约束**：
- **严禁不读大纲直接创作**：必须先完整读取大纲，理解整体架构
- **严禁只读大纲不读章节**：必须读取回顾所有已创作章节，确保连贯性
- **严禁忽略伏笔**：必须对照大纲中的伏笔规划，回收旧伏笔、埋设新伏笔
- **⚠️ 严禁情节原地踏步（关键新增）**：
  - **每一章都必须是情节的推进，而非重复已知信息**
  - **严禁**：本章只是描述主角"继续调查"、"思考现状"、"回忆过去"而无实质进展
  - **严禁**：本章内容与上一章相比，主角处境、认知、目标没有任何变化
  - **严禁**：删除本章后主线仍然连贯（如果可删除，说明本章缺乏推进价值）
  - **必须确保**：本章有新事件、新信息、新冲突、新转折推动主线发展

**详细规则**：参见 [craft/reference/technical-details.md](craft/reference/technical-details.md) 第十五节

**阶段二：正文创作**

**核心规则**：
- 字数：≥3500字
- 结构：开头（引入）→ 发展（冲突升级）→ 高潮 → 结尾（悬念）
- 章节结尾：强制使用悬念机制 + 固定引导句
- 必须遵循人性化写作规范（创作前确认规范在上下文中，若不在则必须重新读取 [craft/reference/humanized-writing.md](craft/reference/humanized-writing.md)；SKILL.md步骤3.2已内嵌核心规范）
- 必须遵循大师级能力系统（参见 [craft/reference/drama-storytelling.md](craft/reference/drama-storytelling.md)）

**章节节奏模板（爽文成瘾工程·长篇每章必执行）**

在「开头→发展→高潮→结尾」四段结构内，叠加如下情绪节奏任务：

```
0-300字    （开头）  │ 钩子锁注意力——直接承接上章悬念，抛出本章新冲突
                     │ 禁止重复交代上章内容，直接切入本章危机
300-2000字 （发展）  │ 压情绪——困境加深/反派施压/蓄力
                     │ 每300字一个小信息点；可有1-2次小爽点但不释放主压力
                     │ 此段是「蓄水池」，越满高潮越爽
2000-3200字（高潮）  │ 爆发——反杀/打脸/揭秘/升级，快准狠，集中释放
                     │ 打脸三要素：当众 + 见证者震惊反应 + 羞辱性
                     │ 若是缓冲章：此段为情感/日常/世界观，强度降档
3200-3500字（结尾）  │ 新钩子——停在最揪心最未知处，不给答案
                     │ 3-2-1布局法：全章最大钩子放在最后200字
```

**爽感参数校准（每章落笔前内部对齐）**：
- 本章在全书是「高能章」还是「缓冲章」（高能:缓冲比 = 3:1或4:1，连续高能超4章须插入缓冲）
- 本章压爽比是否达标（约60%压+30%爆+10%释放）
- 本章三级爽感是否分布合理（小爽×2-3 + 中爽×1-2 + 大爽×0-1）
- 同一反派本章是否已是第3次施压（若是，下一章必须安排反杀，不可拖延）

**创作要求**：
- 开头承接上一章结尾悬念
- 发展部分矛盾逐渐加剧，人物关系深化
- 高潮部分核心冲突爆发，主角面临挑战
- 结尾强制使用悬念机制，引导读者继续阅读
- 埋设1-2个新伏笔，回收1-2个旧伏笔
- 至少包含一个意想不到的情节反转
- 确保情节推进（有新事件、新信息、状态变化）

**【记忆系统】章节后摘要回填（新增）**

1. **生成章节摘要**
   ```python
   chapter_summary = {
   ```

## 长篇期待感专项：双倒计时与跨章伏笔回收

### 双倒计时系统（长篇专属的期待感永动机）

单一倒计时：当下紧迫，但读者知道到点就结束，紧迫感不持久。双倒计时解决这个问题：

- **短期倒计时**：章级，维持当下的紧迫感。"三天内必须找到证据""今晚处决前必须逃跑"——让读者在当前几章内屏住呼吸。
- **长期倒计时**：贯穿全书，给读者"终点在哪儿"的安定感与宏观期待。"百天后大祭/帝位交接/宿命之战"——读者有宏观锚点，不会迷失在漫长章节里。
- **交替推进**：短期倒计时维持近期紧迫，长期倒计时拉住远期期待，两股力量夹住读者，翻页停不下来。
- **实操**：每条倒计时必须在场景里有具体的"计时器"（人物/物件/事件）承载，不能只是叙述性说明"还剩三天"。

### 跨章伏笔回收承诺（百章期待的设计规范）

伏笔回收的期待感跨越整个故事周期，是长篇独有的期待感来源。

- **埋法**：让读者"知道这是伏笔"——不是直接说"这是伏笔"，是用一个特写动作或强调性描写让读者注意到某句话/某个物件。读者想："这里一定有深意。"从此一直惦记它。
- **节奏要求**：每10章内至少有1个伏笔被部分激活（不是回收，是被提起/被推进一步），让读者感到伏笔"还活着"。
- **回收时机**：收在读者已经"快忘了"和"还记得"之间的临界点——太早=没张力，太晚=读者已忘=惊喜感归零。长篇伏笔最优回收窗口约在埋设后30-60章。
- **禁止**：①高潮时突然引入全新信息冒充伏笔回收（这是欺骗，不是伏笔）；②伏笔埋了20章后再无任何激活，读者彻底遗忘后才回收。
- 与narrative-ecology.md第9.4答案问题比联动：每次伏笔被激活（部分推进）时，同步抛出更大的问题，保持问号净增。
