## 第一节：核心创作引擎

### 1.1 引擎工作原理

**核心定位**：默认短篇多方向并行引擎，同时支持长篇连续创作。

**短篇结构变体完整映射**：

**微小说赛道**（800-2200字）：

| 变体名称 | 字数范围 | 节拍数 | 适用场景 | 核心特征 |
|---------|---------|--------|----------|----------|
| **六拍快反** | 800-1000字 | 6拍 | 短平台/快节奏 | 极简结构，强反转 |
| **基础七拍** | 1000-1200字 | 7拍 | 通用/默认 | 标准七拍，平衡完整 |
| **八拍情绪** | 1000-1500字 | 8拍 | 情感/关系/共情 | 道具承载第三层情绪意义 |
| **七拍Plus** | 1200-1600字 | 7拍+ | 短剧改编向 | 强视觉卡点，情绪峰值 |
| **九拍双线** | 1200-1800字 | 9拍 | 解谜/悬疑/复杂叙事 | 明线+暗线并行，结尾交汇 |
| **十拍多重** | 1500-2200字 | 10拍 | 复杂侦探/双层反转 | 反转之后再反转 |

**盐选短篇赛道**（8000字起，知乎盐选平台，最佳1万-1.5万字，详见 [references/zhihu-salt-story.md（本仓未移植，见源包 references/）](zhihu-salt-story.md)）：

| 变体名称 | 字数范围 | 节拍数 | 适用场景 | 核心特征 |
|---------|---------|--------|----------|----------|
| **盐选六拍快反** | 8000-10000字 | 6拍 | 短平台快节奏/知乎引流体升级 | 极简6拍压缩，建置触发合一，受挫35%+反击25% |
| **盐选标准七拍** | 8000-15000字 | 7拍 | 通用/默认盐选投稿 | 每拍1000-3000字空间，标准5%-15%-10%-25%-20%-15%-5%分配 |
| **盐选压抑-爆发** | 8000-15000字 | 7拍（变体） | 爽文/复仇/虐文/逆袭 | 第四拍占40%蓄力，第五拍爆爽释放 |
| **盐选八拍情绪** | 10000-18000字 | 8拍 | 情感/世情/共情/治愈 | 新增"情绪锚点"拍，道具承载第三层情绪意义 |

| **盐选导语前置型** | 8000-12000字 | 6拍 | 倒叙开局/高能开场/强悬念 | 开篇即高潮，倒叙回溯，高潮合流+颠覆反转（盐选独有） |
| **盐选付费卡点型** | 10000-15000字 | 7拍 | 付费转化最大化/免费引流 | 围绕40-50%付费卡点设计，免费段自洽迷你故事（盐选独有） |
| **盐选系列文钩子型** | 8000-15000字 | 8拍 | 系列文/续集引流/长线IP | 本篇闭环+系列伏笔+续集钩子迫读下一篇（盐选独有） |

**字数范围说明**：
- 微小说赛道：**800-2200字**
- 微小说默认输出字数：**800-1500字**
- 微小说丰富档/宇宙档可达：**1500-2200字**
- 盐选短篇赛道（知乎盐选平台）：
  - **8000字起**（最佳1万-1.5万字，详见 [references/zhihu-salt-story.md（本仓未移植，见源包 references/）](zhihu-salt-story.md)）

2. 盐选赛道内，爽文/复仇/虐文/逆袭 → 选择"盐选压抑-爆发"变体
3. 盐选赛道内，快节奏/短平台 → 选择"盐选六拍快反"变体
4. 盐选赛道内，情感/世情/治愈 → 选择"盐选八拍情绪"变体
5. 盐选赛道内，短剧改编/强视觉 → 选择"盐选七拍Plus"变体
6. 盐选赛道内，悬疑/解谜/复杂叙事 → 选择"盐选九拍双线"变体
7. 盐选赛道内，侦探/多层反转 → 选择"盐选十拍多重"变体
8. 盐选赛道内，倒叙开局/高能开场/"从结局讲起" → 选择"盐选导语前置型"变体（盐选独有）

**详细变体说明**：参见 [craft/reference/short-story-template.md](short-story-template.md) "进阶结构变体库"

**引擎特性**：
- **多方向并行生成**：一次性生成5+条不同方向的创作路线
- **智能择优机制**：通过六维打分系统自动选择最优正文路线
- **多样性感知**：确保输出具有明显多样性，避免同质化

**工作流程图**：
```
用户输入 → 智能分析 → 方向簇生成(≥5条) → 多样性门禁检查 → 六维打分 → 择优选择正文 → 输出结果
                ↓
         备用航线(其余4条简述)
```

### 1.2 创作流程概览

| 步骤 | 任务 | 参考文档 |
|------|------|----------|
| 步骤1：智能分析 | 分析用户需求，确定创作类型（短篇/长篇） | 本节 1.1 |

### 1.3 方向簇强制异构规则（核心约束）

**⚠️ 严格规范（强制执行）**

**定义**：方向簇内部必须异构——任意两条候选路线不得在"题材+反转母型"上完全同构。

**异构标准**：
- 任意两条候选路线不得重复"题材+载体"组合
- 正文航线不得与备用航线在"题材+反转母型"上完全同构
- 每条航线至少在一个维度上明显不同（题材/载体/情绪走向/反转母型/余味类型）

**反茧房机制（Anti-Echo Chamber）**：
1. **多样性门禁**：生成方向簇后，自动检测内部同质化程度
2. **重复惩罚**：若发现相似路线，自动重采样直至满足异构要求
3. **显性呈现**：在输出中明确标注各航线的差异维度

**校验机制**：
```
检查项：
□ 任意两条路线题材是否不同？
□ 任意两条路线反转母型是否不同？
□ 任意两条路线情绪走向是否不同？
□ 备用航线与正文是否在上述维度上明显不同？
```

### 1.4 默认短篇输出格式

**触发条件**：用户未指定"丰富档"或"宇宙档"时

**输出结构**（与 SKILL.md 步骤5 微小说格式规范完全一致，必须按此顺序执行）：
1. **标题**：1个爆款标题
2. **正文**：短篇正文（800–1500字）
3. **备用航线**：至少5条简述
4. **六维打分**：4个维度各9-10分
5. **优化建议**：2条具体可执行的优化方向
6. **特色语言风格使用说明**：列出本篇使用的特色语言风格
7. **创作自检报告**：7项检查全部通过
8. **种草提醒**：显示六个技能种草
9. **下一步选择**：话术灵活，种草方式不固定
10. **封面设计**：调用 load_skill 工具加载「社媒封面设计大师」

## 第二节：全向拓展增强包

### 2.1 增强包概述

**定位**：为创作系统提供无限扩展能力的增强模块，支持多维度、多层次的创作增强。

## 第三节：方向簇强制异构规则（详细版）

### 3.1 规则定义

**核心要求**：方向簇（并行生成的候选路线集合）内部必须异构——任意两条候选路线不得在"题材+反转母型"上完全同构。

**异构覆盖最低要求**：
- 任意两条路线不得重复"题材+载体"组合
- 正文航线不得与备用航线在"题材+反转母型"上完全同构
- 每条航线至少在一个维度上明显不同

### 3.2 差异维度定义

**五个差异维度**（至少在一个维度上不同）：

1. **题材维度**：悬疑 vs 言情 vs 科幻...
2. **载体维度**：监控体 vs 聊天记录 vs 日记体...
3. **情绪走向维度**：紧张递进 vs 甜蜜升级...
4. **反转母型维度**：身份错置 vs 因果报应 vs 规则漏洞...
5. **余味类型维度**：时间余震 vs 物证回咬 vs 规则继续...

### 3.3 多样性门禁检查流程

```
生成方向簇（≥5条）
  ↓
执行多样性门禁检查
  ├─ 检查1：题材覆盖度（≥3种不同题材）
  ├─ 检查2：反转母型覆盖度（≥3种不同母型）
  ├─ 检查3：情绪走向覆盖度（≥2种不同走向）
  └─ 检查4：正文与备用差异度（正文与备用不得同构）
  ↓
检查通过？
  ├─ 是 → 进入六维打分
  └─ 否 → 重采样方向簇 → 重新检查
```

### 3.4 反茧房约束（Anti-Echo Chamber）

**约束定义**：
1. **内部异构**：方向簇内部不得同质化
2. **外部探索**：鼓励探索用户未明确要求的题材/风格
3. **新鲜度优先**：优先选择用户未接触过的组合

**重复惩罚机制**：
- 若检测到相似路线，降低其打分权重
- 自动重采样直至满足异构要求
- 最终输出时明确标注各航线的差异维度

### 3.5 异构示例

**示例场景**：用户要求创作"电梯异常"主题

**错误示例（同质化）**：
```
航线1：都市怪谈 + 监控体 + 身份错置
航线2：都市怪谈 + 监控体 + 身份错置  ❌ 与航线1完全同构
航线3：都市怪谈 + 日记体 + 身份错置  ❌ 仅载体不同
```

**正确示例（异构）**：
```
正文：都市怪谈 + 监控体 + 身份错置
航线1：本格侦探 + 工单体 + 密室诡计
航线2：黑镜微科幻 + 聊天记录 + 规则漏洞
航线3：职场反打 + 口供审问 + 动机倒置
航线4：婚恋反转 + 时间线 + 证据互换
航线5：现实寓言 + 通知公告 + 叙述指代误导
```

## 第四节：六维打分标准

### 4.1 打分维度定义

**六个评分维度**（每项满分10分，总分60分）：

| 维度 | 权重 | 定义 | 评分要点 |
|------|------|------|----------|
| 新颖度 | 20% | 题材/载体的创新程度 | 是否避免陈词滥调，是否有新意；是否采用2024-2026爽点新范式（智慧碾压/规则博弈/赛道杂交）而非过时套路 |
| 冲突强度 | 20% | 核心矛盾的尖锐程度 | 冲突是否尖锐，是否有张力；压抑铺垫是否够深（压得越深爽得越狠，参考3:1压爽比），是否建立了让读者"替主角憋着"的读者债 |
| 角色鲜明 | 15% | 人物形象的立体程度 | 人物是否有记忆点，行为是否一致；主角的处境/情绪是否能让读者产生"这就是我"的共鸣，是否替读者喊出了那句没说出口的话 |
| 转折力度 | 20% | 情节反转的震撼程度 | 反转是否出人意料，是否合理；爆发是否对应前文压抑形成情绪落差，打脸是否当众+有见证者+具羞辱性（社交比较爽） |
| 可续性 | 15% | 为后续发展留空间的程度 | 是否留下悬念，是否有延展性；章末/篇末钩是否停在最揪心处（蔡格尼克未完成效应），是否形成"缺一角拼图"的追读拉力 |
| 风格一致 | 10% | 整体风格的统一程度 | 语言风格是否统一，是否有特色 |

### 4.2 评分标准

**各维度评分细则**：

**维度1：新颖度（20%）**
- 10分：开创性题材/载体组合，前所未有
- 8-9分：熟悉的题材+新颖的载体，或新颖的题材+熟悉的载体
- 6-7分：常规组合，但有小创新
- 4-5分：常见组合，无明显新意
- 0-3分：陈词滥调，毫无新意

**维度2：冲突强度（20%）**
- 10分：多重冲突交织，张力十足
- 8-9分：冲突尖锐，推动力强
- 6-7分：冲突明显，但张力一般
- 4-5分：冲突模糊，推动力弱
- 0-3分：无明显冲突

**维度3：角色鲜明（15%）**
- 10分：人物立体，行为逻辑自洽，有记忆点
- 8-9分：人物鲜明，性格突出
- 6-7分：人物基本清晰，但缺乏特色
- 4-5分：人物模糊，行为逻辑有问题
- 0-3分：人物平面，毫无特色

**维度4：转折力度（20%）**
- 10分：反转震撼，情理之中意料之外
- 8-9分：反转有力，有冲击力
- 6-7分：有反转，但冲击力一般
- 4-5分：反转平淡，可预测
- 0-3分：无反转或反转牵强

**维度5：可续性（15%）**
- 10分：悬念设置精妙，为后续留足空间
- 8-9分：结尾有悬念，可延展
- 6-7分：有一定延展性
- 4-5分：结尾较完整，延展性弱
- 0-3分：完全闭环，无法续写

**维度6：风格一致（10%）**
- 10分：风格统一，特色鲜明
- 8-9分：风格基本一致，有亮点
- 6-7分：风格基本统一
- 4-5分：风格有摇摆
- 0-3分：风格混乱，前后矛盾

### 4.3 总分计算

**计算公式**：
```
总分 = 新颖度×0.2 + 冲突强度×0.2 + 角色鲜明×0.15 + 转折力度×0.2 + 可续性×0.15 + 风格一致×0.1
```

**评分等级**：
- 50-60分：优秀，直接采用
- 40-49分：良好，可考虑采用
- 30-39分：一般，需优化
- 20-29分：较差，需大幅修改
- 0-19分：不合格，弃用

### 4.4 自动择优机制

**择优流程**：
```
方向簇生成（≥5条）
  ↓
六维打分（每条路线）
  ↓
计算总分并排序
  ↓
选择最高分作为正文
  ↓
其余作为备用航线
```

**择优原则**：
- 选择总分最高的路线作为正文
- 若多条路线分数相近（差距<3分），优先选择新颖度更高的
- 确保正文与备用航线在题材/反转母型上明显不同

## 第八节：特色语言风格详细说明

### 8.1 毒舌风格

**定义**：犀利吐槽、精准打击、幽默讽刺的语言风格。

**适用场景**：
- 职场反打题材
- 现代都市言情
- 吐槽类轻松向

**技术要点**：
1. **观察精准**：抓住对方最痛/最荒谬的点
2. **比喻犀利**：用出人意料的比喻制造笑点
3. **节奏快速**：短句为主，连珠炮式输出
4. **留有底线**：毒舌但不恶毒，有分寸感

**示例**：
```
"你的方案就像你的发际线——看似还在，其实早就退无可退了。"
```

### 8.2 神回复风格

**定义**：出人意料、一语中的、令人拍案叫绝的回答风格。

**适用场景**：
- 对话场景
- 反转揭示
- 情感冲突

**技术要点**：
1. **打破预期**：回答要出乎对方意料
2. **精准打击**：一句话切中要害
3. **余味悠长**：让人回味
4. **符合人设**：回复要符合角色性格

**示例**：
```
问："你为什么总是一个人？"
答："因为两个人太挤，三个人太吵，零个人刚刚好。"
```

### 8.3 废话风格

**定义**：看似说了很多，实则信息量极低；或故意绕弯子的语言风格。

**适用场景**：
- 讽刺官僚/形式主义
- 营造荒诞感
- 缓解紧张气氛

**技术要点**：
1. **循环论证**：用不同方式说同一件事
2. **过度修饰**：堆砌修饰词但无实质内容
3. **回避核心**：绕开关键问题
4. **喜剧效果**：让读者意识到"这是在说废话"

**示例**：
```
"关于这个问题，我们需要从多个角度、多个层面、多个维度进行深入的、全面的、系统的分析和研究，在充分论证、充分讨论、充分协商的基础上，形成一个共识性的、一致性的、统一性的意见和看法。"
```

### 8.4 风格选择指南

**根据题材选择**：

## 第十三节：短篇高频"爽/恐/反差"机制详解

### 13.1 身份错置

**核心定义**：受害者=叙述者=加害者，但读者直到结尾才意识到重合。

**运作机制**：
1. 叙述者以受害者身份出现，遭遇威胁
2. 读者默认认为叙述者是无辜的受害者
3. 故事过程中埋设暗示，但不明确
4. 结尾揭示叙述者就是加害者/鬼魂/不存在的人

**经典示例**：
```
场景：一个人收到匿名信，警告他小心
叙述：我开始调查，发现所有人都很可疑
反转：匿名信是我自己写的，因为我已经死了
```

**技术要点**：
- 叙述视角必须不可靠，但不能撒谎
- 读者可以事后回溯，发现线索早就存在
- 反转后，前文的理解被彻底改写

**应用场景**：
- 侦探故事：叙述者就是凶手
- 恐怖故事：叙述者已经死了
- 心理悬疑：叙述者精神分裂

### 13.2 因果报应速成

**核心定义**：一次"善意/贪念/侥幸"即刻得到过度报偿或惩罚。

**运作机制**：
1. 主角做出一个选择（善意/贪念/侥幸）
2. 立刻产生结果，但结果是过度的
3. 报偿或惩罚超出合理范围
4. 产生道德反思或恐怖感

**经典示例**：
```
场景：主角捡到一个钱包，决定归还
报偿：钱包的主人其实是富豪，立刻送给他一套房
反转：但这套房子是凶宅，主角住进去后遭遇恐怖事件
```

**技术要点**：
- 结果必须立刻出现，不能延迟
- 结果必须是过度的（超出合理范围）
- 可以是报偿也可以是惩罚，但都会产生负面后果

**应用场景**：
- 道德寓言：善行得到过度回报，但伴随代价
- 警示故事：贪念立刻得到惩罚
- 恐怖故事：侥幸行为引发连锁恐怖事件

### 13.3 日常异化

**核心定义**：家用物、公共空间轻度失常，以"熟悉之物的微偏差"产生寒意，少血腥高想象。

**运作机制**：
1. 场景必须是日常的（家里、办公室、电梯、地铁）
2. 异常必须是轻微的（时间差、声音延迟、影子对不上）
3. 不解释异常的来源，留白让读者想象
4. 通过"熟悉的错位"产生恐怖感

**经典示例**：
```
场景：主角回家，发现自己的钥匙插进锁孔，打不开门
异常：门从里面反锁了，可主角住在12层，没有其他住户
异化：屋里有人，但主角是唯一住户
```

**技术要点**：
- 异常必须是轻度的，不能太夸张
- 异常必须是可感知的，不是幻觉
- 不解释异常的来源，让读者自己想象
- 利用"日常的安全感被打破"产生恐怖

**应用场景**：
- 家居恐怖：钥匙、门锁、镜子、家具
- 公共恐怖：电梯、地铁、商场、办公楼
- 物品恐怖：手机、快递、监控、外卖

### 13.4 记录视角

**核心定义**：监控/工单/外卖单号/快递箱/门禁通行记录成为关键叙事体。

**运作机制**：
1. 通过"非人类"的视角讲述故事
2. 记录本身是客观的，但读者的解读是主观的
3. 记录中的细节成为关键线索
4. 通过记录的"缺失"或"异常"揭示真相

**经典示例**：
```
视角：监控录像记录
内容：凌晨3点，电梯停在12层，林峰走出电梯
异常：监控显示林峰回家了两次，一次3点，一次4点
反转：第二次回家的不是林峰，是鬼魂
```

**技术要点**：
- 记录必须是客观的，不能有主观评价
- 记录的格式要真实（时间戳、地点、人物）
- 通过记录的"细节"埋设线索
- 通过记录的"缺失"产生悬念

**应用场景**：
- 监控录像：电梯、楼道、办公室
- 工单记录：维修、投诉、服务
- 外卖记录：订单、配送、签收
- 门禁记录：进出、时间、身份

### 13.5 规则漏洞

**核心定义**：遵守"楼道规则/租房条款/直播平台条款"反而触发恐怖事件。

**运作机制**：
1. 设定一个明确的规则（楼道规则、租房条款、平台规则）
2. 主角遵守规则，认为这样就能安全
3. 遵守规则反而触发恐怖事件
4. 产生"遵守规则=危险"的反差感

**经典示例**：
```
规则：楼道公告：晚上10点后不要按负一层
主角行为：严格遵守，晚上10点后不按负一层
结果：电梯自动停在负一层，门开了，里面有人
反转：遵守规则反而触发了恐怖事件
```

**技术要点**：
- 规则必须明确，不能模糊
- 主角必须严格遵守，不能违反
- 遵守规则后立即产生负面后果
- 产生"规则本身就是陷阱"的反思

**应用场景**：
- 楼道规则：楼层、时间、行为
- 租房条款：禁止事项、限制条件
- 平台规则：直播、社交、消费
- 社会规则：职场、学校、家庭

### 13.6 节奏控制硬约束（爽文成瘾工程·情节推进铁律）

以下约束来自 2024-2026 年爆款数据实证，不达标即影响完读率与追读率。

**章节标准节奏模板（3000字章节）**

```
0-300字     │ 钩子锁注意力（冲突/危机/反转）——多巴胺启动
300-1500字  │ 压情绪（反派嘲讽→陷入困境/蓄力）——情绪蓄水池
1500-2500字 │ 小爆发（反击/打脸/拿到关键线索）——内啡肽触发
2500-3000字 │ 新悬念（勾下章，停在最揪心处）——蔡格尼克未完成
```

> 这个模板是底层结构，适用于所有拍/章节，与七拍/九拍等上层结构叠加使用：上层结构决定「有几个叙事单元」，此模板决定「每个单元内的情绪节奏」。

**信息密度控制**

| 场景类型 | 节奏 | 句法规范 | 信息点频率 |
|---------|------|---------|----------|
| 打架/追杀/反转/打脸 | 快 | 短句+对话+动作，禁用长描写段 | 每100-150字一个 |
| 铺垫/感情/世界观 | 慢 | 描写+心理+细节，可用长句 | 每300字一个 |
| 过渡/日常 | 中 | 混合，注意不连续两段同节奏 | 每300字一个 |

> **通用底线**：任何场景每300字必须出现至少一个「小信息点/小冲突/小悬念」，超过300字无新信息即产生流水账感，读者犯困。

**三禁原则（情绪曲线）**

- ❌ **禁止一直平**：超过300字无任何信息波动=流水账，读者犯困直接划走
- ❌ **禁止一直爽**：连续3章以上满负荷爽点=无压力感，很快腻，爽点失效
- ❌ **禁止一直虐**：超过3章无正向爽感信号=情绪过载，直接弃书

**打脸节奏硬性约束**

- 同一反派欺负/羞辱主角**不超过3次**——第4次起即变「憋屈文」，读者会弃书
- 反派完整节奏：**挑衅 → 5-10章内完成反杀 → 主角收获奖励 → 新地图/新级别反派**
- 打脸必须「当众+有见证者旁观反应+羞辱性（以彼之道还施彼身）」三要素同时满足
- 打脸后立即给主角实质奖励（资源/身份/人脉），让爽感有落点而非单纯宣泄

**爽点密度配比（每章3000字标准）**

| 爽点层级 | 数量 | 单次篇幅 | 出现间隔 |
|---------|------|---------|---------|
| **小爽点** | 2-3个 | 一句话/一个动作 | 每300-500字 |
| **中爽点** | 1-2个 | 500-800字 | 每章1次 |
| **大爽点** | 1个 | 多章铺垫、集中释放 | 每3-5章 |

**情境具体化原则（共鸣落地的硬要求）**

抽象的情绪不留人，具体的情境才留人。**禁止用一句概括代替一个场景。**

| 弱写法（抽象，读者无感） | 强写法（具体情境，读者秒代入） |
|----------------------|---------------------------|
| 他在公司受了很多委屈 | 方案是他熬三个通宵写的，组长当众念出的却是自己的名字，他张了张嘴，最后只说了句「应该的」 |
| 她很不甘心 | 同期入职的都升了职，她还在改第八版PPT，凌晨两点整层楼只剩她一盏灯 |
| 主角被亲戚瞧不起 | 年夜饭桌上，三舅当着全家问他「一个月挣那点钱，够干嘛的」，他夹菜的手停在半空 |

> 情境越具体、越有画面、越像真发生过，共鸣越深、代入越强、越舍不得弃书。这是 drama-storytelling 3.5「从主题下沉到情境」在技术层的强制落地，也直接喂养视觉卡点。

**五种弃书情绪（完读率杀手，逐一规避）**

源自情绪传播实证，对小说同样致命——每一种都是读者中途划走的直接原因：

| 失败模式 | 读者反应 | 规避方法 |
|---------|---------|---------|
| **只虐不爽（只有憋屈没有出口）** | 越读越累，看完更压抑 | 任何憋屈/焦虑必须在可控章节内兑现爽的释放 |
| **只爽不铺垫（爽点没有压抑垫底）** | 爽得很空，很快腻 | 爽点前必须有压抑蓄力，遵守压爽比 |
| **只共鸣不推进（一直在说"你懂我"）** | 觉得说得对，但没新东西，弃 | 共鸣之后必须给反转/升级/新信息 |
| **只信息不情绪（流水账/设定堆砌）** | 知道有用，但不想看 | 每段都要带情绪温度，信息裹在冲突里给 |
| **钩子骗进来正文接不住** | 被骗感，信任崩塌，弃书且不回 | 章末钩抛出的悬念，后文必须如约兑现 |

> 这五条与本节「三禁原则」「打脸节奏铁律」、drama-storytelling 3.5 共鸣红线共同构成完读率防线。

## 第九节：创作后优化询问机制

### 9.1 机制概述

**触发时机**：创作完成后，向用户询问优化方向。

**询问结构**：
```
【优化方向】
1. 篇幅调整：是否需要扩展/压缩？
2. 情节调整：反转力度、冲突强度是否需要调整？
3. 风格调整：语言风格是否需要改变？
4. 细节调整：人物、场景、对话是否需要修改？
5. 方向切换：是否想尝试其他备用航线？

【快速指令】
- 输入"扩写"：扩展当前内容
- 输入"改写"：重新创作
- 输入"改这段：[粘贴片段]+目标"：段落级手术改写（只动该片段）
- 输入"压缩"或"压缩到X字"：压缩当前内容至目标字数
- 输入"扩感官：[片段]"：五感沉浸扩写（调用五感沉浸引擎）
- 输入"诊断本章"：输出3行结构反馈（长篇章节按需）
- 输入"走第N路"：切换到第N条备用航线
- 输入"下一章"：继续下一章
```

### 9.2 快速响应规则

**用户输入指令后的响应**：

| 用户输入 | 响应动作 |
|----------|----------|
| "扩写" | 扩展当前章节，增加细节和场景 |
| "改写" | 基于相同大纲，重新创作 |
| "改这段：[片段]+目标" | **段落级手术改写**：只重写用户粘贴的片段（目标可为调性如"更狠/更悬疑"、力度、或指定字数），其余正文一字不动；改后过 humanized-writing + narrative-ecology 自检；长篇同步核验与追踪文件的人物气质、伏笔一致性 |
| "压缩" / "压缩到X字" | 压缩当前章节或指定片段至目标字数；压缩优先级：保钩子＞保爽点＞保伏笔＞砍过渡与冗余描写，压后特色语言配额不得跌破赛道底线 |
| "扩感官：[片段]" | 调用 `craft/reference/sensory-craft-engine.md` 五感沉浸引擎：判场景类型+POV角色→按第七节配方选2+1感官→按感知顺序嵌入动作行→默认扩至1.5-2倍（可指定字数）→过反AI感官腔自检→只输出扩写结果 |
| "诊断本章" | （长篇按需，不自动输出）3行结构反馈：本章节奏（快/慢/合格+一句依据）、人物着墨（谁被写薄了）、章末钩子强度（1-10分+一句改法）；不展开长篇报告，用户要细则再说 |
| "走第N路" | 切换到第N条备用航线作为正文 |
| "下一章" | 继续创作下一章 |
| "丰富档" | 增加备用航线数量到8条 |
| "宇宙档" | 增加备用航线数量到12条+3种终句候选 |

### 9.3 优化反馈循环

```
创作完成
  ↓
询问优化方向
  ↓
用户反馈
  ├─ 满意 → 结束/继续下一章
  ├─ 不满意 → 根据反馈优化
  └─ 切换方向 → 选择备用航线
```

  ├─ 确定整体语言风格

  └─ 按照规范格式输出完整大纲
  ↓

```

### 6.1bis 种草·封面·插画触发矩阵（与 SKILL.md 步骤5/步骤6对齐，强制执行）

> **同步声明**：本矩阵与 SKILL.md「输出格式规范」为同一规则。核心区分：种草提醒与封面设计是**单次交付场景**的转化引导（短篇完成 / 长篇大纲完成各触发一次）；长篇章节是**连续创作流程**，只生成插画、不种草不封面，避免每章打断阅读节奏。

| 场景 | 正文/主体 | 种草提醒 | 封面设计 | 插画 |
|------|----------|---------|---------|------|
| **微小说/盐选短篇**（创作完成后） | 正文+备用航线+六维打分 | ✅ 必须（6技能，每次表达不同） | ✅ 调用社媒封面设计大师 | ❌ 不生成 |
| **长篇大纲**（完成后） | 大纲内容 | ✅ 必须（6技能，每次表达不同） | ✅ 调用社媒封面设计大师 | ❌ 不生成 |
| **长篇章节**（第1章/续写完成后） | 正文+特色语言+自检 | ❌ 不触发 | ❌ 不触发 | ✅ 必须生成（默认竖版2:3） |

**插画比例规则（强制，长篇章节专属）**：长篇章节插画**比例严格固定 2:3 竖版**（书籍标准竖版），**严禁输出 16:9、1:1 或其他比例**；必须章节正文创作完成后才能绘图（禁止边写边画）；仅 1 张，特别必要最多 2 张；长篇章节不进入"改编短剧/改编漫画"询问。

**依附关系链（长篇章节为何全部不触发）**：短剧转化引导、对抗式小说审核种草均依附于种草提醒之后同批次输出；长篇章节无种草提醒，故这两项自然不出现。

## 第七节：章节创作通用规则

### 7.1 章节字数要求

**硬性规定**：
- **最低字数**：每章 ≥ 3500字
- **推荐字数**：3500-5000字
- **超长章节**：可适当放宽至8000字（需情节支撑）

**字数分配建议**：
| 部分 | 占比 | 字数 | 功能 |
|------|------|------|------|
| 开头（引入） | 15% | 500-750字 | 承接悬念，引入新情节 |
| 发展（冲突升级） | 40% | 1400-2000字 | 矛盾加剧，人物深化 |
| 高潮 | 25% | 875-1250字 | 核心冲突爆发 |
| 结尾（悬念） | 20% | 700-1000字 | 设置悬念，引导续读 |

### 7.2 章节结构要求

**标准四段式结构**：

**开头（引入）**：
- 承接上一章的结尾悬念
- 引入新的情节元素
- 设置本章的核心冲突

**发展（冲突升级）**：
- 矛盾逐渐加剧
- 人物关系深化或变化
- 引入新的线索或障碍

**高潮**：
- 本章核心冲突爆发
- 主角面临重大挑战或抉择
- 情节达到情绪峰值

**结尾（悬念）**：
- **强制使用悬念机制**（四种悬念写法之一）
- 为下一章铺垫
- 保持读者的阅读欲望

### 7.3 四种悬念写法

**悬念类型1：揭示悬念**
```
在第[数字]章中，[主角]将发现[关键线索/真相]，这将彻底改变[当前局势/人物关系]。
```

**悬念类型2：冲突预告**
```
然而，[主角]并不知道，[某个威胁/阴谋]正在暗处悄然逼近，而[相关人物]的命运也将因此发生剧变。
```

**悬念类型3：人物行动**
```
面对[当前困境]，[主角]决定[采取的行动]，但这一选择将把[他/她]卷入[更大的危机/秘密]之中。
```

**悬念类型4：未知威胁**
```
就在[当前事件]看似告一段落时，[某个异常/新的线索]突然出现，暗示着[更大的阴谋/危险]才刚刚开始……
```

### 7.4 章节结尾引导句格式

**标准格式**：
```
📖 本章结束，输入「下一章」继续解锁：[主角]在[事件]中[行动]，[悬念点]即将揭晓，下一场[剧情预告]即将开启……
```

> ⛔ **章节节点强制停顿（与 SKILL.md 章节停顿闸门对齐）**：输出本引导句后**立即停止**，等待用户明确说"下一章"/"续写"/"继续"。**严禁自动开始下一章**。表格/流程中"下一章→继续创作"指收到用户该指令后才执行，不得理解为可连续自动产出。

**示例**：
```
📖 本章结束，输入「下一章」继续解锁：林峰在地下室发现死亡证明，确认自己三年前已死，真相的冰山一角即将揭晓，下一场寻找死亡原因的冒险即将开启……
```

### 7.5 伏笔管理规则

**每章必做**：
- **埋设新伏笔**：每章至少埋设1-2个新伏笔
- **回收旧伏笔**：每章至少回收1-2个旧伏笔
- **记录状态**：在追踪文件中更新伏笔状态

**伏笔类型**：
1. **核心伏笔**：贯穿全文的关键线索（3-5个）
2. **次要伏笔**：单卷或数章内的线索（5-8个）
3. **临时伏笔**：本章或下章回收的小线索（灵活）

### 7.6 插画生成规则

**生成时机**：每章创作完成后

**数量限制**：
- **默认**：每章1张
- **上限**：特别必要的场景最多2张

**场景选择**：
1. **高潮场景**：本章最精彩的情节
2. **关键场景**：对剧情有重大影响的场景
3. **情感场景**：人物关系突破的场景

**提示词格式**：
```
🖼️ **场景描述**：[本章亮点场景描述]
🖼️ **生成提示**：[用于AI生成插画的提示词]
```

### 7.7 文字质量要求

**基础要求**：
- 语言流畅，文笔优美
- 符合小说的整体风格和主题
- 至少包含一个意想不到的情节反转

**进阶要求**：
- 人物塑造立体，行为逻辑自洽
- 情节推进合理，因果关系清晰
- 情绪节奏把控得当，爽点设置合理

---


### 7.8 每章情绪锚点（强制）

**定义**：每章至少有一个让读者产生情绪反应的节点——爽、虐、甜、笑、紧张、愤怒均可。情绪锚点可以很小，但必须存在。无情绪锚点的章节=过渡章=读者划走的章。

**自检**：这章里有哪一刻读者的情绪会发生变化？如果答不上来，该章需要补一个情绪节点再交付。锚点不需要是大反转，一句让人会心一笑的对话、一个让人心疼的细节，足够。

### 7.9 情绪释放节奏（压-弛波形）

长篇章节不能一直紧，紧张感是翻页动力，但持续高压=读者疲劳=真正高潮时没感觉。爆款长篇遵循的节奏：**紧张→释放→更紧张→更大的释放**。

- 释放的节点往往是读者最爽的时刻：打脸、表白、认可、拯救。
- **憋多久决定释放有多爽**：每次释放前的蓄压长度，直接决定读者的情绪爆发强度。
- **实操**：章内至少有1次小压弛（局部紧张→局部释放）；大压弛跨章安排，不可每章都高潮（否则高潮变平均，等于无高潮）。
- 与narrative-ecology.md第2条"爽点打断(delay/denied/cost)"联动：打断=蓄压；当章兑现损失=小释放；最终爽点=大释放。节奏是跨章的，单条代价规则是章内的，两者是不同粒度。

### 7.10 高潮后的回响段落（强制，不可跳章）

**问题**：高潮写完立刻进入下一件事，读者刚被情绪推到顶峰，还没来得及消化，作者换台了。读者的情绪投入等于白费。

**规则**：高潮（打斗/对峙/告白/真相揭露）结束后，必须有一个**回响段落**再收章——不是长篇大论的后果交代，是用一小段、一个安静的瞬间、一个具体的细节，展示**这件事对人物造成了什么改变**。

- 示例手法：让他站在阳台一根接一根抽烟；让他坐在床边很久没动；让他盯着一样东西发呆，什么都没看进去。
- 硬性要求：回响段落必须有**人物身体层面的反应**（不是内心独白总结），长度50-150字，禁止用"第二天早上，他像往常一样起床"直接跳过。
- 与sensory-craft-engine.md联动：回响段落是体内感官（肌肉/呼吸/胃部）的天然落点，不是心理总结的场所。

## 第十五节：长篇小说上下文管理规范

### 15.1 章节创作前的必读检查清单

**⚠️ 每次创作新一章节前，必须按顺序执行以下检查**：

#### 检查1：读取初始大纲（必须执行）

**读取内容**：
- 主题立意、世界观设定
- 核心冲突、主角核心欲望
- 三幕式结构规划
- 事件团拆解
- 人物关系梳理
- 章节划分（总章节数、关键转折点）
- 伏笔规划（核心伏笔、次要伏笔）

**验证要点**：
- 确保当前章节符合大纲规划
- 确保人物性格与初始设定一致
- 确保情节推进符合三幕式结构

#### 检查2：读取所有已创作章节内容（必须执行，必须实际调用工具）

**⚠️ 关键纠正：严禁只读上一章，严禁假读取**

**正确做法（强制执行）**：
- **必须使用read_file工具逐章读取**：对每一章文件调用read_file工具，**严禁跳过**
- **必须读取文件内容**：不是读文件名，不是读文件列表，是读**文件内容**
- **必须能复述内容**：读取后必须能复述每章的核心事件和结尾悬念（无法复述=没读）
- **必须读取从第1章到最新章的所有章节**：第1章包含原始设定，中间章节包含发展脉络，最新章包含直接承接点

**读取验证（证明真的读了）**：
读取完成后，必须能回答以下问题（无法回答=没读）：
- 第1章的核心事件是什么？（要求复述具体内容，不是概括）
- 上一章结尾的具体悬念是什么？（要求复述原文细节，不是"留下悬念"这种空话）
- 当前未回收的伏笔有哪些？分别是在哪一章埋设的？

**严禁（违者严肃处理）**：
- ❌ **严禁"声称读取"但实际未调用read_file工具**：这是欺骗行为
- ❌ **严禁只读文件名或文件列表**：必须读取文件**内容**
- ❌ **严禁仅依赖对话上下文记忆**：必须重新读取文件
- ❌ **严禁只读最近2-3章**：必须读第1章（原始设定）+所有中间章节（发展脉络）+最新章（直接承接）
- ❌ **严禁基于大纲概要猜测章节内容**：大纲是规划，章节是实际内容，两者可能不同

#### 检查3：读取长篇创作规范（必须执行）

**读取内容**：
- 章节字数要求（≥3500字）
- 章节结构要求（开头→发展→高潮→结尾）
- 章节结尾悬念机制（四种悬念写法）
- 章节结尾引导句格式
- 伏笔管理规则
- 插画生成规则

#### 检查4：验证伏笔回收状态（必须执行）

**检查内容**：
- 列出已埋设但未回收的伏笔清单
- 检查当前章节是否需要回收某个伏笔
- 检查当前章节是否需要埋设新伏笔

#### 检查5：验证人物关系一致性（必须执行）

**检查内容**：
- 主角当前状态（性格、情感、目标）
- 配角当前状态（与主角的关系、功能）
- 人物关系网是否有变化

#### 检查6：验证情节推进度（必须执行）

**⚠️ 核心原则：每一章都必须是故事的推进，而非原地踏步**

**情节推进的硬性要求**：
- **必须有新事件发生**：本章必须发生至少1个推动主线的新事件
- **必须有信息增量**：本章必须揭示至少1个新的关键信息
- **必须有状态变化**：主角或关键人物的状态、目标、认知必须有变化
- **必须向前发展**：情节必须比上一章更进一步

**推进度验证清单**：
```
□ 本章是否有新冲突爆发？（是/否）
□ 本章是否有重要发现/揭示？（是/否）
□ 本章结束时主角处境是否与章首不同？（是/否）
□ 本章是否回收或埋设了关键伏笔？（是/否）
□ 本章是否推动主线向结局靠近？（是/否）
□ 如果删除本章，主线是否还能连贯？（如果"是"，说明本章缺乏推进价值）
```

### 15.2 章节创作前的必问问题

**在开始创作新一章节前，必须回答以下问题**：

1. **当前是第几章？总共有几章？**
   - 答案示例：当前是第15章，总共有50章
   - 目的：确保章节进度符合大纲规划

2. **当前章节属于哪个情节团？**
   - 答案示例：属于第二幕"冲突升级"情节团
   - 目的：确保情节推进符合三幕式结构

3. **上一章结尾是什么悬念？**
   - 答案示例：主角发现监控录像里的人是自己
   - 目的：确保新章节承接上一章悬念

4. **本章需要回收哪些旧伏笔？**
   - 答案示例：需要回收"电梯停在不存在楼层"的伏笔
   - 目的：避免伏笔遗忘

5. **本章需要埋设哪些新伏笔？**
   - 答案示例：埋设"保安的真实身份"伏笔
   - 目的：为后续情节铺垫

6. **本章的人物关系有什么变化？**
   - 答案示例：主角与保安的关系从陌生变为信任
   - 目的：确保人物关系变化有逻辑

7. **本章的情绪爽点在哪里？**
   - 答案示例：在第3500字处，主角发现关键线索
   - 目的：确保情绪节奏合理

8. **⚠️ 本章的核心推进事件是什么？（关键新增）**
   - 答案示例：主角发现了隐藏地下室的入口，这是推动主线向真相靠近的关键一步
   - 目的：**强制确认本章有情节推进，而非原地踏步**

9. **⚠️ 本章结束时与章首相比，主角状态有何变化？（关键新增）**
   - 答案示例：章首主角还在怀疑保安，章末已经确认保安是知情人，目标从"调查"变为"追踪保安"
   - 目的：**强制确认主角有实质成长/变化，而非回到原点**

### 15.3 章节创作后的必做检查

**创作完成后，必须执行以下检查**：

#### 检查1：验证字数
- 检查字数是否≥3500字
- 如果字数不足，必须补充内容

#### 检查2：验证结构
- 检查是否有开头（引入）
- 检查是否有发展（冲突升级）
- 检查是否有高潮
- 检查是否有结尾（悬念）

#### 检查3：验证悬念机制
- 检查是否使用了四种悬念写法之一
- 检查悬念是否足够吸引人
- 检查悬念是否为下一章铺垫

#### 检查4：验证引导句
- 检查是否使用了固定引导句格式
- 检查引导句是否准确预告下一章内容

#### 检查5：验证伏笔管理
- 检查是否埋设了1-2个新伏笔
- 检查是否回收了1-2个旧伏笔
- 检查伏笔是否自然、不刻意

#### 检查6：验证人物一致性
- 检查人物性格是否与初始设定一致
- 检查人物行为是否合理
- 检查人物关系变化是否有逻辑

#### 检查7：验证连贯性
- 检查是否承接了上一章的结尾
- 检查情节是否连贯
- 检查是否有情节断层

### 15.5 长篇小说连贯性保障机制

**为避免30-100章后内容脱节，建立以下机制**：

#### 机制1：每5章强制回顾
- 每完成第5、10、15、20...章后，强制回顾初始大纲
- 验证人物性格、情节推进是否符合初始设定

#### 机制2：伏笔清单管理
- 建立已埋设伏笔清单
- 每章创作后更新清单状态（已回收/未回收）
- 在每10章时检查是否有未回收的伏笔

#### 机制3：人物状态快照
- 每10章记录一次人物状态快照
- 包括：主角性格、人物关系、关键事件
- 确保人物成长弧光连贯

#### 机制4：情节进度检查
- 每10章检查一次情节进度
- 验证是否符合三幕式结构
- 确保不会偏离主线

### 15.6 长篇小说常见问题与解决方案

| 问题 | 原因 | 解决 |
|------|------|------|
| 人物性格走偏 | 忘记初始设定 | 每次创作前读取初始大纲的人物设定 |
| 情节断层 | 没有承接上一章结尾 | 每次创作前读取上一章内容+大纲内容|
| 伏笔遗忘 | 没有建立伏笔清单 | 使用伏笔清单管理机制 |
| 风格不一致 | 忘记长篇创作规范 | 每次创作前读取第7节规范 |
| 结局偏离 | 忘记初始大纲的结局规划 | 每2章强制读取回顾初始大纲 |

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
检查结论：[✅ 通过 / ⚠️ 已自动补齐]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 执行规则：
- **任一项为"不存在"**：**自动创建/补齐**，继续创作流程，不中断
- **任一项为"未读取"**：**禁止创作**，必须先执行读取流程
- **全部显示"已读取"或"已自动创建"**：允许进入正文创作阶段
- **自动创建后提示**：简要说明已创建的文件内容，提示用户如需修改可手动编辑

#### 保存时强制更新规则：
- 章节文件保存完成后，**必须立即**更新追踪文件
- 追踪文件更新内容包括：章节状态、字数、完成时间、伏笔状态、人物状态
- **严禁**延迟更新追踪文件

#### 长篇大纲创建时：
```
1. 创作大纲内容（步骤3）
2. 输出大纲格式（步骤5）
3. 创建目录：mkdir -p novel-creation-evo-output
4. 保存大纲文件：novel-creation-evo-output/[标题]_大纲.md
5. 创建追踪文件：novel-creation-evo-output/[标题]_追踪.md（初始状态）
6. 执行步骤6（封面+种草）
```

#### 长篇章节创作时：
```
1. 读取大纲文件（步骤0）
2. 读取追踪文件（步骤0）
3. 读取所有已创作章节文件（步骤0）
4. 创作章节内容（步骤3）
5. 输出章节格式（步骤5）
6. 保存章节文件：novel-creation-evo-output/[标题]_第X章.md
7. 更新追踪文件：novel-creation-evo-output/[标题]_追踪.md
8. 执行步骤6（仅插画+引导句，长篇章节不触发种草/封面）
```

### 16.5 文件读取规范（续写时必须遵循）

#### 读取顺序（强制执行）：
```
第一步：读取大纲文件
  └─ novel-creation-evo-output/[小说标题]_大纲.md

第二步：读取追踪文件
  └─ novel-creation-evo-output/[小说标题]_追踪.md

第三步：读取所有章节文件
  └─ 列出目录：ls novel-creation-evo-output/[小说标题]_第*.md
  └─ 按顺序读取：第1章 → 第2章 → ... → 最新章

第四步：状态核对
  └─ 对比追踪文件中的"当前完成章节数"与实际读取的章节文件数量
  └─ 如不一致，以实际文件为准，更新追踪文件
```

#### 读取确认（必须在创作前执行）：
```markdown
📋 **文件读取确认**
✅ 已读取大纲文件：[路径]
✅ 已读取追踪文件：[路径]
✅ 已读取章节文件：
   - [小说标题]_第1章.md
   - [小说标题]_第2章.md
   - ...
   - [小说标题]_第X章.md（最新）
✅ 章节数量核对：追踪文件记录[X章] = 实际文件[X章]
✅ 人物状态已同步
✅ 未回收伏笔已清单化
```

### 16.6 常见问题与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| 文件保存失败 | 目录不存在或权限问题 | 自动创建目录 `mkdir -p novel-creation-evo-output` |
| 追踪文件与章节文件不一致 | 某章保存成功但追踪文件更新失败 | 以实际章节文件为准，重新生成追踪文件 |
| 续写时找不到文件 | 工作目录变更或文件路径错误 | 严格按照 `novel-creation-evo-output/` 相对路径读取 |
| 大纲文件丢失 | 未执行保存或保存路径错误 | 每次大纲创作完成后强制执行保存 |

### 16.7 文件管理最佳实践

1. **及时保存**：每章创作完成后立即保存，不要等待用户确认
2. **同步更新**：章节文件和追踪文件必须同步更新，不能只更新其一
3. **读取确认**：续写前必须确认所有文件已正确读取，严禁跳过
4. **状态标记**：追踪文件中的"状态"列必须准确反映创作进度
5. **备份意识**：重要节点（如大纲完成、卷末）可以创建备份文件

### 11.2 O-10：短篇爆款输出格式（默认）

**触发条件**：用户未指定特殊档位时默认使用

**结构选择**：根据2.5节决策树选择最适合的结构变体

| 结构变体 | 字数 | 适用场景 | 核心特征 |
|---------|------|----------|----------|
| **基础七拍** | 1000-1200字 | 通用/默认 | 标准七拍，平衡完整 |
| **九拍双线** | 1200-1800字 | 解谜/悬疑/复杂叙事 | 明线+暗线并行，结尾交汇 |
| **八拍情绪** | 1000-1500字 | 情感/关系/共情 | 道具承载第三层情绪意义 |
| **六拍快反** | 800-1000字 | 短平台/快节奏 | 极简结构，强反转 |

| **七拍Plus** | 1200-1600字 | 短剧改编向 | 强视觉卡点，情绪峰值 |

**基础七拍配比（参考字数）**：
1. **开场钩子**（100–150字）：直接抛出异常/缺失/禁忌
2. **设定递进**（160–250字）：人物-场景-欲望/困境
3. **初次错位**（130–190字）：抛出误导性线索，引导读者早判
4. **加码证据**（160–220字）：二证/道具回访
5. **主反转**（195–280字）：彻底颠覆既定解释
6. **终点回击**（80–125字）：以一句/一物重锚主题
7. **余味一击**（1句/30字内）：给续写口或二次反思

**其他变体节拍说明**：参见short-story-template.md"进阶结构变体库"

**标题建议**：「日常物 + 反常动因 + 悬问/后果」

**示例标题**：
- 《停电后的第12层》
- 《她把快递放回了门外，门却从里面上锁》

**完整示例**：

```markdown
**标题**：《她只是按了电梯的-1》

**正文**：

电梯停在了12层——这栋楼只有11层。

我按了关门键，没反应。门开得更大了，一个女人站在那里，穿着红裙子，脸看不清。"能帮我按个B1吗？"她的声音很轻，像是从井底传上来的。

我皱眉，这栋楼确实没有负一层，但我还是按了B1。电梯门关上了，显示屏开始跳动：1...2...3...直到11，然后跳到了12。叮的一声，电梯停住了。

门开了，外面不是12层，是一条昏暗的走廊，尽头有一扇门，门缝里透出红色的光。"谢谢。"女人走出电梯，消失在走廊里。

我想追上去，但电梯门已经关上，显示屏回到了1层。我惊出一身冷汗，赶紧冲出电梯，跑回自己家。

第二天，我问保安，昨晚有没有异常。保安说："昨晚有个女人跳楼了，就死在电梯口。她穿着红裙子。"

我愣住了，"哪个电梯口？"

"就是你住的那栋楼。"

我立刻回家，打开电视看新闻。新闻里说，死者是一名独居女性，住在12层。但我那栋楼只有11层。

我想报警，但警察说监控拍得很清楚，她是自己跳下去的。监控画面里，她按了电梯，电梯上行，停在12层，她走出来，走到走廊尽头，从窗户跳了下去。

我看着监控，突然发现一个问题。监控里，电梯停在12层后，门开了一条缝，然后关上了。但她并没有走进电梯。她是从电梯里走出来的。

她不是上楼，她是下楼。

我再次看监控，慢放。凌晨三点，电梯从12层下来，停在1层。门开了，女人走出来。但她不是往外走，而是往回走，退进了电梯。电梯门关上，显示屏开始下行：1...B1...B2...

电梯一直在往下，直到负无穷。

原来，她不是要上12层，她是想下去。下去到她该去的地方。

监控还有最后一段没看，但我知道，我不该看。

---
**余味**：
那栋楼现在拆了，但电梯还在。
```

### 11.3 O-11：小说正文输出格式（长篇章节）

**⚠️ 创作规范**：本节所有示例仅作学习参考，严禁抄袭或模板化。

**结构**：章节标题 → 完整章节正文（≥3500字）

**章节标题要求**：
- 每章都应有一个吸引人的章节标题
- 概括本章的核心内容或悬念
- 标题格式：可使用数字编号（第1章、第2章...）或独立标题

**章节结构要求**：
- **开头（引入）**：承接上一章或引入新情节，设置悬念
- **发展（冲突升级）**：矛盾逐渐加剧，人物关系深化
- **高潮**：本章核心冲突爆发，主角面临挑战
- **结尾（悬念）**：强制使用悬念机制，引导读者继续阅读

**文字要求**：
- 语言流畅，文笔优美，符合小说的整体风格和主题
- 每章字数保持在3500字以上（或用户指定范围内）
- 续写的故事中至少包含一个意想不到的情节反转

**完整示例（节选）**：

```markdown

就在门即将关上的瞬间，他看到黑暗中有一个身影，站在走廊尽头，一动不动。

那个身影，穿着和他一样的衬衫。

```

### 11.4 O-12：续写部分输出格式

## 第十二节：定义示例详解

### 12.1 D-1：事件团拆解示例

**核心定义**：围绕主角的愿望设置多个核心危机，形成具有多重危机的事件团。

**拆解方法**：
1. 确定主角的核心欲望（如：想要查明真相）
2. 围绕欲望设置3个层次的危机（低→中→高）
3. 每个危机对应一个事件团，每个事件团包含3-5个关键事件
4. 事件团之间环环相扣，形成情节链

**完整示例**：

```markdown
**小说《电梯停在12层》事件团拆解**

**主角核心欲望**：查明电梯异常的真相

**第一事件团（低危机）：异常显现**
- 事件1.1：电梯显示屏跳到12层
- 事件1.2：电梯停在12层并开门
- 事件1.3：收到第一条警告短信"别出去"
- **危机等级**：低（只是现象异常，未造成实际伤害）

**第二事件团（中危机）：威胁升级**
- 事件2.1：回家后发现家中被监视
- 事件2.2：收到第二条警告短信"别开灯"
- 事件2.3：发现发送号码是0000
- 事件2.4：电梯自动上行到12层
- **危机等级**：中（威胁到主角的居住安全）

**第三事件团（高危机）：真相暴露**
- 事件3.1：保安说出"你根本不存在"
- 事件3.2：查看监控录像，发现自己已经死亡
- 事件3.3：发现监控最后一段未揭示的内容
- **危机等级**：高（颠覆主角的存在认知）

**事件团关联**：
- 事件团1 → 事件团2：异常显现后，威胁进入私人空间
- 事件团2 → 事件团3：威胁升级后，真相被揭示
```

### 12.2 D-2：情节链构建示例

**核心定义**：将事件团组合成情节链，使剧情环环相扣，形成有效的叙事结构。

**构建方法**：
1. 确定故事的核心冲突
2. 按照时间顺序排列事件团
3. 在事件团之间设置转折点（激励事件、情节点1、中点、情节点2）
4. 确保因果关系合理，伏笔埋设自然

**完整示例**：

```markdown
**小说《电梯停在12层》情节链构建**

**核心冲突**：林峰面对"自己已死"的真相，如何接受并超越死亡

**情节链（线性结构）**：

**第1章**
- 激励事件：林峰发现电梯停在12层
- 事件团1.1：电梯显示屏跳到12层
- 事件团1.2：电梯停在12层并开门
- 事件团1.3：收到第一条警告短信"别出去"
- **结尾悬念**：看到和自己穿一样衬衫的身影

**第2章**
- 事件团2.1：回家后发现家中被监视
- 事件团2.2：收到第二条警告短信"别开灯"
- 事件团2.3：发现发送号码是0000
- 事件团2.4：电梯自动上行到12层
- **结尾悬念**：保安说"你根本不存在"

**第3章**
- 情节点1：林峰决定调查真相
- 与保安对话，得知真相线索
- 查看电梯维修记录
- **结尾悬念**：保安说"三年前你就死了"

**第4章**
- 中点：林峰查看监控录像
- 事件团3.1：监控显示自己已经死亡
- 事件团3.2：发现监控最后一段未揭示的内容
- 高潮：林峰接受死亡事实
- **结局**：林峰超越死亡，电梯继续向下运行

**因果链**：
电梯异常 → 发现警告短信 → 发现被监视 → 保安揭示真相 → 查看监控 → 接受死亡

**伏笔链**：
- 开头：电梯停在12层 → 结尾：林峰已死，12层是死亡代号
- 中途：0000号码 → 结尾：死亡代号
- 结尾：监控最后一段 → 留下续写口
```

## 第十四节：侦探关键术语详解

### 14.1 不在场证明

**核心定义**：以时间证据否证作案可能；通过交通时间/电子记录/物理距离穿透。

**运作机制**：
1. 嫌疑人声称自己在案发时不在现场
2. 侦探调查嫌疑人案发时的行踪
3. 通过交通时间、电子记录、物理距离验证
4. 发现不在场证明的漏洞或伪造

**经典示例**：
```
嫌疑人声明：案发时我在公司开会
调查：公司门禁记录显示嫌疑人18:00离开，案发时间是18:30
漏洞：公司到案发现场需要20分钟，嫌疑人来不及作案？
真相：嫌疑人通过伪造门禁记录制造不在场证明
```

**技术要点**：
- 不在场证明必须有客观证据支持
- 时间线必须精确到分钟
- 考虑交通、天气、路线等因素
- 发现证据的矛盾点

**常见不在场证明类型**：
- 电子记录：门禁、监控、通话记录
- 人证：目击证人、同事、朋友
- 交通证据：车票、导航记录、监控录像
- 物理距离：计算从A到B的时间

### 14.2 密室

**核心定义**：封闭空间的表面不可能性，实际通过时差/替换/误导观察实现。

**运作机制**：
1. 案发现场是封闭的，没有出入口
2. 看起来凶手无法进入或离开
3. 实际上通过诡计实现
4. 诡计类型：物理诡计、叙述性诡计、时间诡计

**经典示例**：
```
案发现场：房间门窗紧锁，钥匙在死者口袋里
表面不可能性：凶手无法进入或离开
诡计：凶手通过气窗进入，作案后从气窗离开，最后用钓鱼线把钥匙放进死者口袋
破绽：气窗上有划痕，死者口袋有压痕
```

**技术要点**：
- 密室必须表面无法解释
- 诡计必须有合理性
- 诡计必须有可执行的细节
- 必须留下微证据供读者发现

**常见密室诡计类型**：
- 物理诡计：气窗、管道、暗道
- 替换诡计：钥匙替换、尸体替换
- 时间诡计：作案时间与发现时间错开
- 误导诡计：误导观察者的注意力

### 14.3 叙述性诡计

**核心定义**：视角/时序/指代/省略制造误读，禁止无提示的作者欺诈。

**运作机制**：
1. 通过叙述手法误导读者
2. 改变视角、时序、指代关系
3. 关键信息被省略或暗示
4. 结尾揭示真相，读者可回溯发现线索

**经典示例**：
```
叙述：我回到家，发现妻子躺在地上，已经死了
误导：读者默认叙述者是丈夫
反转：叙述者是妻子，"我"指的是妻子的鬼魂
线索：前文提到"我看不到自己的倒影"
```

**技术要点**：
- 必须有提示，不能无提示欺骗读者
- 误导必须是合理的，不能撒谎
- 反转后，前文的理解被改写
- 读者可以事后回溯，发现线索早就在

**常见叙述性诡计类型**：
- 视角诡计：叙述者身份误导
- 时序诡计：时间顺序错位
- 指代诡计：代词指代不明
- 省略诡计：关键信息被省略

### 14.4 红鲱鱼

**核心定义**：误导线索，可被逻辑排除且不与真相矛盾。

**运作机制**：
1. 嫌疑人或线索看起来很可疑
2. 读者以为是真凶或关键线索
3. 通过逻辑推理排除
4. 不与真相矛盾，只是误导

**经典示例**：
```
红鲱鱼：保安老王，案发时监控缺失1分钟
怀疑点：监控缺失，有作案机会
排除：老王有明确的不在场证明（医院病历）
真相：真凶是楼长，利用监控缺失嫁祸保安
```

**技术要点**：
- 红鲱鱼必须看起来可疑
- 红鲱鱼必须有合理的怀疑理由
- 红鲱鱼必须能被逻辑排除
- 红鲱鱼不能与真相矛盾

**红鲱鱼的作用**：
- 增加推理难度
- 引导读者走向错误方向
- 提升真相揭晓时的震撼感
- 展示侦探的推理能力

### 14.5 后期反转强度等级

**Level-1 主反转**：翻倒显性解释
- 将读者默认的理解完全翻转
- 改变对整个故事的认知
- 示例：受害者=加害者

**Level-2 真相反转**：改写动机/时序/身份
- 在主反转基础上进一步揭示
- 改变对核心问题的理解
- 示例：动机不是复仇，而是保护

**Level-3 情感/立意反转**：同情/正义立场倒置
- 改变读者的情感立场
- 改变对人物的评价
- 示例：反派其实是在做正义的事

**Level-4 终句回击**：一物/一句重写全文意义
- 用最后一句话改写全文意义
- 产生余味和反思
- 示例："那栋楼拆了，但电梯还在。"

**经典示例（阶梯反转）**：
```
L1主反转：林峰发现自己已经死了（身份错置）
L2真相反转：林峰是自己自杀的，但遗忘了（动机改写）
L3情感反转：保安其实是林峰的潜意识，试图唤醒他（同情倒置）
L4终句回击："那栋楼拆了，但电梯还在。"（余味延展）
```

**技术要点**：
- 反转必须层层递进，不能一次全部揭晓
- 每层反转都要有合理性
- 每层反转都要有微证据支持
- 终句回击要简洁有力，改写全文意义
