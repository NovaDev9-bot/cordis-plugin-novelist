## 一、文档定位与使用原则

这份手册不是素材摘要，也不是单次聊天记录整理稿，而是面向AI小说创作系统的"上层控制文档"。

它的目标是把所有原始内容统一转换成一套可检索、可拼装、可扩展、可维护的知识库骨架，让AI在收到用户需求后，能够立刻完成四件事：

1. 识别用户真正要什么
2. 快速找到最该调用的模块
3. 用统一顺序拼出可写的大纲、开头、桥段、感情推进和细节表达
4. 在用户卡文时，准确定位问题并给出可执行修复方案

这份文档服务的不是"好看"，而是"高效调用"。

**四条核心原则**：
1. 结构优先于堆料
2. 索引优先于摘要
3. 路由优先于灵感
4. 修复优先于空泛建议

## 六、三条调用路径

### 路径A：从零开始创作
1. 先调开篇模块，确定钩子与气质
2. 再调主线模块，确定发动机
3. 再调题材模块，确定世界规则
4. 再调角色模块，确定主角、对手、关系对象
5. 再调剧情驱动层，补中段事件与冲突
6. 再调用情绪/虐梗/拉扯子库，提升密度
7. 最后调用表达层，完成开头、对白、微动作和神态落地

### 路径B：用户只给题材，要求出方向
1. 先锁题材层
2. 再从主线模块给3到10条发动机备选
3. 为每个方向补1条核心关系和1条卖点
4. 最后给可用开头句方向

### 路径C：用户已经有故事，但写不动
1. 先进入问题修复层
2. 判断卡在开头、中段、感情、高潮、结尾还是表达
3. 再回调缺失模块，而不是直接空泛建议

## 七、标准化检索标签

后续总知识库建议统一采用纯文本标签检索，不用复杂表格，不用散乱目录名。

推荐统一格式：
```
【题材】+【主线】+【关系】+【情绪】+【主角模型】+【交付目标】
```

示例：
- 【现代都市】+【事业】+【协议恋爱】+【拉扯】+【事业脑女主】+【十章大纲】

## 十、主库功能定位与适用边界

为了让AI不误用素材，必须明确每个主库到底解决什么问题。

### 10.1 499剧情母题库的定位
它不是"完整故事"，而是"章节事件池"。
- **适合用来**：
  - 补中段事件
  - 补生活细节
  - 补古言现言桥段
  - 补人物关系互动场面
- **不适合**：直接拿来当完整主线

### 10.2 69虐梗库的定位
它不是用来随便撒刀，而是用来建立代价、错过、无法挽回和命运压迫。
- **适合用来**：
  - 提升情绪密度
  - 建立虐点层次
  - 设计高潮崩塌段
  - 建立BE/意难平结构

### 10.3 CP人设库的定位
它不是单独剧情，而是"人物关系引擎"。
- **适合用来**：
  - 快速选CP组合
  - 生成男女主职业反差
  - 生成敌对/合作/治愈型关系框架

### 10.4 极限拉扯库的定位
它不是恋爱主线本身，而是"关系推进润滑器"。
- **适合用来**：
  - 写暧昧
  - 写试探
  - 写靠近与后退
  - 写未说出口的情绪

### 10.5 微动作库的定位
它不是故事驱动层，而是"文本表现层"。
- **适合用来**：
  - 让情绪具象化
  - 让人物说话前先有反应
  - 替换直白总结句
  - 给场景增加真实触感

### 10.6 黄金开篇库的定位
它是开局加速器，不是整本书答案。
- **适合用来**：
  - 定第一句
  - 定开头三段
  - 定语气与世界异常感
  - 给多个方向做第一句备选

### 10.7 女频必火梗库的定位
它是女性向主线和人设赛道索引。
- **适合用来**：
  - 选女主赛道
  - 选身份逆转模型
  - 选高概念感情模板
  - 选事业和亲情并行主线

### 10.8 爆文剧情与高效冲突库的定位
它是连载推进引擎和平台节奏模块。
- **适合用来**：
  - 生成可追更主线
  - 提供稳定冲突源
  - 搭高频反转与信息差
  - 给连载做章节级推进骨架

## 十一、AI创作禁止行为

为了确保知识库能长期稳定使用，AI调用时应避免以下问题。

1. 不要把所有库一次性堆进正文
2. 不要只会罗列梗，不做主次划分
3. 不要混淆"主线发动机"和"局部桥段"
4. 不要拿微动作代替剧情推进
5. 不要拿虐梗代替人物逻辑
6. 不要让高概念脱离题材规则独立漂浮
7. 不要把所有用户需求都默认写成恋爱主线
8. 不要卡文时只说"加冲突"，必须明确加哪种冲突
9. 不要输出只有灵感，没有结构的散乱建议
10. 不要为了短期好看而删掉原始素材

## 十二、卡文诊断与修复框架

卡文时，一定先定位原因，再修，不要盲补。

### 12.1 开头卡
- **表现**：
  - 第一页没钩子
  - 第一段全是说明
  - 语气不对
- **修复**：
  - 回调黄金开篇库
  - 强制加入异常、秘密、矛盾或特殊设定
  - 第一段只做一件事：让读者想看第二段

### 12.2 主线卡
- **表现**：
  - 开头热闹，后面不知道写什么
  - 只有人物关系，没有持续驱动力
- **修复**：
  - 回调爆文主线库或女频必火梗库
  - 强制补1个主驱动与1个副驱动

### 12.3 中段卡
- **表现**：
  - 连续解释，事件停滞
  - 人物只聊天，不行动
- **修复**：
  - 回调499剧情母题库与120高效冲突库
  - 每章必须加入事件、阻碍、偏差或新信息

### 12.4 感情卡
- **表现**：
  - 明明是感情线，但没有上头感
  - 两个人互相喜欢却没有障碍
- **修复**：
  - 回调关系模型库与极限拉扯库
  - 增加身份限制、误解、代价、错位、试探和中断

### 12.5 虐点卡
- **表现**：
  - 想虐但不痛
  - 只流泪，没有真正代价
- **修复**：
  - 回调虐梗库
  - 至少引入一种"无法轻易弥补的损失"：时间、身份、生命、误会、记忆、责任

### 12.6 人物卡
- **表现**：
  - 人物像功能纸片
  - 只会说情绪，不会表现情绪
- **修复**：
  - 回调微动作库和神态库
  - 用动作、呼吸、眼神、手势替换总结句

### 12.7 结尾卡
- **表现**：
  - 冲突结束得太顺
  - 结尾没有余味
- **修复**：
  - 回调终极目标冲突与代价模块
  - 明确主角到底失去了什么、保住了什么、完成了什么

## 十三、最终交付给AI的两套版本

为了真正方便系统调用，建议最终做成两套文件。

### 13.1 完整主知识库总册
特点：
- 保留全部素材
- 可追溯原始来源
- 做深度查找和后续扩容

### 13.2 AI快速调用前端手册
特点：
- 只有索引、路由、规则、模块说明
- 模型首轮读取速度快
- 用于立即判断"该去哪查"

当前这份文档，属于第二种。

## 十四、后续整编时的标准动作

真正开始做总册时，建议严格按以下顺序推进。

### 第一步：建立RAW层
把每一批原文单独存好，确保一个字不丢。

### 第二步：建立索引层
把原始内容按六层结构挂载到对应模块。

### 第三步：建立标签层
给每一条素材打标签：题材、主线、关系、情绪、功能、适用场景。

### 第四步：建立调用层
为AI建立最短路径说明，告诉它什么情况下先用什么。

### 第五步：建立修复层
把卡文、节奏、人物、结尾等问题单独做成诊断手册。

## 十五、结论

先有路由规则，再有分类索引，再有原始素材，再有调用模板，再有问题修复。

AI在接到任何创作任务时，就能够：
- 迅速理解用户要求
- 迅速定位最相关的内容
- 迅速拼出适合该用户需求的创作方案
- 迅速在卡文时找到问题并修复
