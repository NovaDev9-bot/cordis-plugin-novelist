## 1. 四问结构（每个场景必答）

每个场景动笔前，用四问锁定：

| 问 | 答什么 |
|---|---|
| 目标 | 这个场景要推进什么？（主线/角色/伏笔三选一或组合） |
| 阻力 | 什么挡着主角达成目标？（人/环境/自身） |
| 结果 | 目标达成没？付出什么代价？ |
| 转折 | 场景结束，局面哪里变了？（新信息/新关系/新危机） |

四问缺一不可。答不出"目标"的场景 = 不该写。

## 2. 结果三型

场景结果只能是三类之一（或组合）：

1. **推进型**：主线/支线向前一步
2. **揭示型**：新信息曝光，改变读者/主角认知
3. **转折型**：关系/力量对比变化

> 禁止"无结果"场景（见 No-and-nothing 水场景）。

## 3. 500 字章纲铁律

每章章纲最少 500 字，必须含：

- 2–4 个场景，每个写清「目标/阻力/结果/转折」（四问）
- 三层冲突推进：内心冲突（角色 vs 自己）/ 人际冲突（角色 vs 角色）/ 外部冲突（角色 vs 环境）各自推进什么
- 主线推进点：本章在主线脊柱上推进了什么？（见 conflict-engine.md）
- 爽点/钩子：本章爽点是什么？章末钩子什么类型？
- 弧光节点：涉及角色弧光的哪一段？（见 character-arc-engine.md）
- 因果承接：接上章什么因？本章埋什么果？

**禁止章纲少于 500 字。** 章纲是施工图，不是灵感备忘。

## 4. No-and-nothing 水场景

识别标准：场景结束，**目标没推进、关系没改变、信息没新增**——任何一项都没发生 = 水场景。

处理：发现即删，或重写成"有结果"的场景（塞入一个转折/一个新信息）。

## 5. 场景与主线关系

每个场景必须：推进主线 / 深化角色 / 埋设伏笔，三者至少占其一。与主线无关的场景必须删除（哪怕文笔好）。
