# 动态追踪文件系统（Dynamic Story Bible）

> **移植件 · 外部来源（未经本仓校对）**
> 来源 = 外部技能包 novel-workshop-pro（WorkBuddy 专家，上架名「网文主编」）；原始路径 = references/dynamic-story-bible.md；移植日 2026-09-26。
> **取用边界**：本件可能含指标式表述（百分比／密度／配额／占比）。那类量归**审校侧与主编参考**用；
> **不得整段复制进写手派工包**——口径见 craft/author-cards/_模板与建卡纪律.md 的四分界表（进包只许「结构节拍」与「形态上限」两种形状）。
> **取用方式**：按本章场景功能取相应小节，**上限 2 节**；「相关的都塞」是禁止项（guide v7.14）。

> **文件定位**：解决问题4——追踪文件不是锁死的固定模板，而是随故事情节演进自动扩展结构的「活体文档」。
>
> **核心原则**：追踪文件在第1章时是精简的基础结构；随着故事出现新势力、新关系、新阶段、新谜题，追踪文件主动新增对应模块，永远与当前故事复杂度匹配。
>
> **强制触发时机**：每章记忆工作报告完成后，执行「结构演进检测」，判断是否需要新增追踪模块。

## 一、追踪文件生命周期

### 阶段1：基础层（第1-5章，故事建立期）

```markdown
# [书名]_追踪文件 v1.0

## 🔖 故事DNA（永久不变层）
- 书名：
- 核心前提（一句话）：
- 风格基调：[关键词]
- 风格guardrails（不可越过的风格边界）：
- 总体故事弧（三幕结构简述）：

## 👥 人物档案
### [主角名]
→ 见 character-aura-engine.md 气质身份证格式
（本层至少填写：核心欲望/内在伤口/气质锚三件套/OOC红线/弧光轨迹）

### [主要配角/反派]
→ 见 character-aura-engine.md 配角快速档案格式

## 📋 剧情线
| 线名 | 类型 | 当前状态 | 起始章 | 预计高潮章 |
|------|------|---------|------|----------|
| [主线] | 主线 | 进行中 | 1 | - |

## 📎 伏笔账本
| 编号 | 伏笔内容 | 埋设章 | 计划回收章 | 当前状态 |
|------|---------|------|-----------|---------|
| F001 | | 1 | | 🔵未回收 |

## 📖 章节摘要
### 第1章：[标题]
- 核心事件：
- 信息增量：
- 人物状态变化：
- 结尾悬念（原文）：
- 字数：

## ➡️ 当前续写锚点
- 上章悬念：
- 当前紧张点：
- 待回收伏笔（优先级）：
```

### 阶段2：扩展层触发规则

以下每个触发条件出现时，立即向追踪文件新增对应模块：

#### 触发条件A：出现新势力/阵营（第N章）
**新增模块**：
```markdown
## ⚔️ 势力图谱（第N章新增）
| 势力名 | 核心目标 | 当前实力 | 与主角关系 | 出场章 |
|-------|---------|---------|----------|------|
| | | | | |

### 势力关系矩阵
- [势力A] vs [势力B]：[盟友/敌对/复杂]
- [势力A] vs [主角]：[关系]
```

#### 触发条件B：出现复杂人物关系网（人物≥5人且关系交叉）
**新增模块**：
```markdown
## 🕸️ 关系网络（第N章新增）
### 核心关系轴
- [主角] ↔ [角色A]：[关系性质] | 张力来源：[原因]
- [主角] ↔ [角色B]：[关系性质] | 张力来源：[原因]

### 隐藏关系（读者尚未知晓）
- [角色X] ↔ [角色Y]：[真实关系] | 揭示计划：第[N]章
```

#### 触发条件C：进入新地理/空间（重要场景地点≥3个）
**新增模块**：
```markdown
## 🗺️ 世界/空间图（第N章新增）
| 地点名 | 功能 | 已知规则/限制 | 重要事件 | 当前状态 |
|-------|------|------------|---------|---------|
| | | | | |
```

#### 触发条件D：出现时间线复杂性（闪回/多线叙事/时间跳跃）
**新增模块**：
```markdown
## ⏱️ 时间线图（第N章新增）
### 主时间线
| 章节 | 故事内时间 | 关键事件 |
|------|----------|---------|

### 闪回/平行线
| 章节 | 所属时间层 | 内容 | 与主线关联 |
|------|---------|------|---------|
```

#### 触发条件E：核心谜题/悬案出现（悬疑/推理/惊悚题材）
**新增模块**：
```markdown
## 🔍 谜题追踪（第N章新增）
### [谜题名称]
- 提出章节：第[N]章
- 当前已知线索：
  - 线索1（第X章）：
  - 线索2（第X章）：
- 当前疑点：
- 读者可能的判断：
- 真相（作者内部）：
- 揭示计划：第[N]章
```

#### 触发条件F：故事进入新阶段（明显的幕次切换）
**新增模块**：
```markdown
## 🎭 叙事阶段标记（第N章更新）
| 阶段 | 章节范围 | 主题词 | 主角状态 | 反派状态 |
|------|---------|------|---------|---------|
| 第一幕 | 1-[N] | | | |
| 第二幕 | [N]-[M] | | | |（进行中）
```

#### 触发条件G：出现需要追踪的道具/资源/系统（玄幻/系统流）
**新增模块**：
```markdown
## ⚗️ 系统/道具追踪（第N章新增）
| 名称 | 获得章 | 能力/效果 | 使用记录 | 当前状态 |
|------|------|---------|---------|---------|
```

#### 触发条件H：反派复杂度提升（反派有独立动机线）
**新增模块**：
```markdown
## 👹 反派世界观档案（第N章新增）
→ 见 villain-engine.md 反派灵魂档案格式
（本模块追踪反派的自洽逻辑演进，确保反派不退化为纸片人）

### 反派认知地图
| 时间点 | 反派认知 | 读者认知 | 认知差（制造何种效果）|
|--------|---------|---------|-------------------|
| 第[N]章 | | | 可恨/可笑/可悲 |
```

---

### 阶段3：高密度层（≥50章，长篇后期）

当故事超过50章，追踪文件自动激活「信息密度管理」：

```markdown
## 🗂️ 信息归档层（第50章激活）

### 已归档章节（降权处理）
第1-30章核心信息浓缩（每章一句话）：
- 第1章：[一句话]
- 第2章：[一句话]
...

【说明：已归档章节的详细摘要不再占用主要工作记忆，
但原始摘要仍保留在文件底部，需要时可调取。】

### 活跃工作记忆（近20章完整保留）
第31章起，仍保留完整章节摘要格式。
```

**归档触发规则**：
- 每超过20章，将最早的10章降权归档
- 归档不等于删除，可通过"查找[章节]"调取原始详情

## 二、结构演进检测清单（每章后执行）

章节完成后，在输出记忆工作报告的同时，检查以下7项：

```
【追踪文件结构演进检测】

▸ 是否出现了新势力/阵营？    是 → 新增⚔️势力图谱 / 否 → 跳过
▸ 人物关系是否变得复杂？      是 → 新增/更新🕸️关系网络 / 否 → 跳过
▸ 是否进入新地理/空间？       是 → 新增/更新🗺️世界图 / 否 → 跳过
▸ 是否出现时间线复杂性？       是 → 新增⏱️时间线图 / 否 → 跳过
▸ 是否出现核心谜题？          是 → 新增🔍谜题追踪 / 否 → 跳过
▸ 是否进入明显的新叙事阶段？   是 → 更新🎭叙事阶段标记 / 否 → 跳过
▸ 反派动机线是否加深？        是 → 更新👹反派世界观档案 / 否 → 跳过

当前追踪文件版本号：v[X.X]（每次新增模块，版本号+0.1）
```

## 三、追踪文件版本号规则

| 版本 | 触发条件 | 说明 |
|------|---------|------|
| v1.0 | 第1章建立 | 基础层 |
| v1.1-v1.9 | 每次新增模块 | 扩展层生长 |
| v2.0 | 进入第二幕或第30章 | 阶段切换 |
| v3.0 | 进入第三幕或第60章 | 后期高密度层 |

版本号在每次追踪文件更新时标注在文件头部，让用户知道追踪文件有多完整。

## 四、追踪文件与记忆工作报告的联动

| 记忆工作报告发现 | 追踪文件对应动作 |
|----------------|---------------|
| 新人物首次登场 | 立即在人物档案新增条目 |
| 伏笔新增 | 立即在伏笔账本新增行 |
| 伏笔回收 | 标记为✅，移入已回收区 |
| 势力关系变化 | 更新势力图谱 |
| 谜题新线索出现 | 更新谜题追踪 |
| 角色状态发生重大变化 | 更新人物档案弧光轨迹 |
| 进入新叙事阶段 | 更新叙事阶段标记，版本号+0.1 |

---

## 五、追踪文件健康度指标（在记忆报告中显示）

```
追踪文件：v[X.X] | 已启用模块：[N]个 | 
最近更新：第[X]章 | 健康状态：✅活跃 / ⚠️滞后
```

**滞后判定**：连续3章追踪文件无任何更新，且故事有实质进展→标记⚠️滞后，强制更新。
