# 记忆可视化报告系统（Memory Visibility Engine）

> **移植件 · 外部来源（未经本仓校对）**
> 来源 = 外部技能包 novel-workshop-pro（WorkBuddy 专家，上架名「网文主编」）；原始路径 = references/memory-visibility-engine.md；移植日 2026-09-26。
> **取用边界**：本件可能含指标式表述（百分比／密度／配额／占比）。那类量归**审校侧与主编参考**用；
> **不得整段复制进写手派工包**——口径见 craft/author-cards/_模板与建卡纪律.md 的四分界表（进包只许「结构节拍」与「形态上限」两种形状）。
> **取用方式**：按本章场景功能取相应小节，**上限 2 节**；「相关的都塞」是禁止项（guide v7.14）。

> **文件定位**：解决问题3——记忆模块必须在每章完成后输出可见工作报告，让用户确认它在科学有效地持续工作。
>
> **强制规则**：任何长篇章节创作完成后，在章节正文输出后、引导句之前，必须输出「📊 记忆模块工作报告」。不输出 = 记忆系统本次未执行 = 严重错误。
>
> **报告对用户完全可见**，不属于内部流程，是章节输出的必要组成部分。

## 二、报告各模块说明与执行规范

### 2.1「本章已写入追踪文件的内容」
**目的**：让用户看到这一章的信息密度是否达标。

**执行规则**：
- 核心事件必须是**推动主线的事件**，不能是"主角在思考"或"气氛渐渐凝重"——这些不算事件
- 信息增量必须是**读者新知道的内容**，若本章没有任何新信息揭示，则标注"⚠️本章信息密度不足，建议在下章补充"
- 字数须为实际统计值

### 2.2「人物状态更新」
**目的**：证明人物弧光在动，不是原地踏步。

**气质检查判断标准**：
- ✅：本章该角色的所有对话/动作/反应，能通过「名字遮盖测试」
- ⚠️：某段对话/反应看起来像另一个角色说的，具体指出位置

### 2.3「伏笔账本」
**目的**：最关键的记忆模块——防止伏笔失忆。

**超时警报规则**：
- 任何伏笔搁置 ≥ 5章，自动触发 🔴警报
- 任何伏笔搁置 ≥ 10章，触发 🚨紧急警报，必须在下一章给出处理方案

**警报输出格式**：
```
🔴 伏笔超时警报：「[伏笔内容]」已搁置[X]章（第[X]章埋设），请规划回收时机。
🚨 伏笔失控警报：「[伏笔内容]」已搁置[X]章，超出安全阈值！下一章必须回收或明确延期理由。
```

### 2.4「特色语言配额执行」
**目的**：强制确认每章的特色语言配额已达标（问题6执行验证）。

**配额标准**（详见 `craft/reference/witty-style-guide.md`）：
- 微小说：5-8句
- 短篇小说：13-15句
- 长篇每章：7-12句

**未达标处理**：在报告中标注⚠️，并立即补写到正文中，直到达标后再输出最终正文。

### 2.5「风格健康度」
**目的**：防止长篇写到后期风格漂移。

**常见漂移信号**：
- 原本克制的猫腻风开始出现大段心理独白
- 原本口语的孔二狗风开始用书面长句
- 叙事视角在单章内意外切换

### 2.5b「爽感·共鸣健康度」
**目的**：防止长篇连载到后期"爽感漏气、共鸣断线"——这是 v2.5-2.6 双引擎（爽文成瘾工程 + 共鸣引擎）在记忆层的守门，与风格/人物/伏笔同等重要。

**五项判据**（对应 `craft/reference/drama-storytelling.md` 3.5 + `craft/reference/technical-details.md` 13.6 + 强制要求A-2）：
- **压爽比**：本章压抑铺垫与爆发释放比例是否健康（参考约6:3），警惕"只压不爽"（连续憋屈→弃书）与"只爽无铺垫"（爽点发空）
- **共鸣锚点**：开篇/立项时选定的共鸣情绪（委屈/不甘心等）是否在本章延续，主角是否仍在"替读者喊出没说出口的话"，避免越写越偏离最初打动读者的那口气
- **爽点密度**：本章小/中/大爽点数量是否符合配比（小爽每300-500字、中爽每章、大爽每3-5章）
- **读者债**：建债/偿债是否平衡，积压欠债是否在安全区（长期只建不偿=憋屈过载）
- **章末钩兑现**：上一章章末钩本章是否兑现（蔡格尼克钩空挂会崩塌信任）

**未达标处理**：在报告中标注⚠️并给出下一章的修正方向（如"下章必须释放积压两章的打脸债"）。

### 2.6「下一章激活包」
**目的**：这是整个记忆系统最重要的功能——确保下一章续写时有精确的上下文锚点，而不是靠对话记忆模糊地"记得大概"。

**承接悬念规则**：必须引用章末原文，不能概括。原文细节（具体的词、具体的场景）才是真正的续写锚点。

## 三、简化版报告（短篇/微小说适用）

短篇和微小说**不启用记忆系统**（见步骤1.1记忆硬绑定规则），因此**没有记忆工作报告**；下面这份是纯「创作报告」（确认字数/钩子/特色语言配额），与记忆无关，仅作单篇交付的质量回执：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 创作报告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
▸ 字数：[实际字数] | 目标：[赛道要求] ✅ / ⚠️差[N]字
▸ 开场机制：[使用的钩子类型] | 55字测试 ✅ / ⚠️
▸ 特色语言：毒舌[N]句 / 神回复[N]句 / 废话[N]句 / 合计[N]句
  配额要求：[13-15句（短篇）/ 5-8句（微小说）] ✅ / ⚠️差[N]句
▸ 结构变体：[使用的拍数结构]
▸ 核心钩子（结尾）：✅有 / ⚠️弱
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 四、记忆健康度总评（每10章输出一次）

每完成第10、20、30…章时，在标准报告基础上追加「记忆健康度总评」：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📈 记忆健康度总评 · 第[X]-[Y]章
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【主线推进速度】
▸ [X]章内完成了几个主要情节节点：[N]个
▸ 推进评估：✅正常 / ⚠️停滞（连续[N]章无重大推进）/ 🚀过快

【人物弧光追踪】
▸ [主角名] 第[X]章状态 → 第[Y]章状态：[关键词变化]
▸ 弧光支撑：✅有具体事件链 / ⚠️变化缺乏事件支撑

【伏笔健康度】
▸ 已回收：[N]条 / 待回收：[N]条 / 超时警报：[N]条
▸ 伏笔总评：✅健康 / ⚠️[问题]

【特色语言使用趋势】
▸ 近[X]章平均：[N]句/章 | 目标：7-12句
▸ 趋势：✅稳定 / ⚠️递减（可能疲劳）/ 📈递增

【风格漂移检测】
▸ 对比第1章风格设定，当前章节：✅无漂移 / ⚠️偏移（[方向]）

【爽感·共鸣趋势】
▸ 近[X]章压爽比走势：✅稳定 / ⚠️[长期高压无释放 / 长期平淡无爽点]
▸ 共鸣锚点延续：✅初始情绪锚点仍在发力 / ⚠️已偏离最初打动读者的核心情绪
▸ 读者债总账：积压[N]条，最老第[X]章——✅安全 / ⚠️需在近几章集中偿还
▸ 章末钩兑现率：[N]/[N] ✅ / ⚠️有空挂

【总体健康分】：[X]/10
【建议行动】：[1-2条具体建议]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 五、报告执行位置

在章节正文输出结构中，报告的位置固定：

```
[章节标题]
[完整正文（≥3500字）]

━━━ 📊 记忆模块工作报告 ━━━
[本文件第一节的标准格式]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📖 [章节引导句，引导用户输入"下一章"]
```

**绝对不允许**：正文输出后直接跳到引导句，跳过记忆报告。
