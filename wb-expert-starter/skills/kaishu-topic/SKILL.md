# 开书选题

> 协议全文 = `references/protocols/选题协议.md`（v1.1）。**选题是权责级动作，编辑部只呈报不定案。**
> **用户不需要知道流程——开书轮由主编主动提议并带队走完。**

## 输入四件

1. **扫榜数据（可持续账本）**：读番茄/起点榜单页，快照+结论落 `vault/market/选题数据/扫榜-YYYY-MM-DD.md`（**跨书趋势积累**：题材涨落/断层/新贵，每期对比上期）。JS 重页面读不全 → 挂事项板评估浏览器工具。
2. **题材边界**：该赛道什么能写/什么不能写（平台红线 + 读者预期）。
3. **竞争密度**：榜单前 50 同题材占位、头部断层情况。
4. **自身差异化**：拆书资产卡支撑的差异化主张（对锚书"学什么/不学什么"）。

## 选题报告（`editorial/reports/选题-日期.md`）

| 项 | 内容 |
|---|---|
| 候选方向 ×2-3 | 各带：赛道热度证据 / 竞争密度 / 差异化主张 / 锚书资产支撑（卡名） |
| 推荐方向 | 一句话理由 + **风险两问**（最可能扑的点 / 平台审查敏感点） |
| 首卷假想 | 主角 + 金手指 + 第一卷承诺（一段话，不展开） |

## 流程

```
主编主动提议 → 主笔产报告 → 主编汇总取舍 → Owner 拍板 → 拍板结果回写 board/issue-NNN
→ 拆书方向锁定 → 走开书流程（novel_init）
```

## 纪律

- 扫榜结论**必须带榜单快照坐标**（日期+页面）——榜单类信息自带时效，规则会变。
- **不做"我觉得会火"裸结论**；每个候选至少 1 本锚书资产卡背书。
- `novel_init` 是 Owner ask 门：**WorkBuddy 无宿主 ask 门 → 自守门**，呈报并等确认后再建书工程。
