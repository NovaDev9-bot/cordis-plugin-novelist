# 弧级审查

> 机制细则 = `references/novelist-guide-v7.NN.md`「弧级审查」段。**报告给人读，结论必须同时是数据**——否则"这弧承重点在哪""伏笔收支对不对"每次都得重新通读全卷，仪器也消费不了。

## 频率与触发

- **常规**：每 5-10 章一次（锚定事件块边界，**每卷至少 1 次**）。
- **异常触发 · 未发表期**：试读连续 2 章 P0 ／ 修订单未处理积压 > 5 条（含弧审订单）。
- **异常触发 · 已发表期**追加：外审打回率 > 30%（一个事件块内）。
- 默认锚 Owner 可调、bible 可覆盖。

## 三问（全部带证据坐标，禁"我觉得"）

1. 弧线**在轨还是漂移**
2. **伏笔收支**对不对
3. **差异化是否真落地**

## 产出（两个都要，缺一不算完成）

1. **报告** `reports/弧审-卷X-弧Y.md`（给人读）
2. **结构化账单** `novel_ledger op=arc_review` → `editorial/arcs.jsonl`（append-only）：
   - 弧名 / 起止章 / **承重点章号（须在区间内）** / 价值翻转 / 差异化是否落地 / 在轨或漂移 / 证据坐标 / **伏笔收支对**（引用不存在的伏笔 id 会被拒收）

`novel_ask kind=arcs` 可问出账单。

## 派工与回流

- 派**档案员**做对账（只读不写）；弧审时结构校准员可做**全卷扫描**（九类结构病）。
- **写手不列席**，意见经修订单回流：跨块弧审意见落 `orders/arc-卷X-弧Y/` 并计入积压锚，章内意见仍走 `block-XXX`。
- **落账权唯一在主编**——档案员只读不写，账单由主编落。

## 卷尾结算（另一条，别混）

卷写完且收束后 **6 章内**（一个批次）报一次「卷 N 结算」：卷内未收伏笔 / 未闭欠线 / 未兑现钩子逐类点名，**过后静默**。
它在 `novel_verify` 的 `warnings`（业务提示）而非 `issues`（硬清单）——结算清单每次卷末必出一条，混进 issues 就成了"每收一卷必红"，红灯贬值后真问题也看不见。
