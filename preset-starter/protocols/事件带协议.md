# 事件带协议（2026-09-05 · 产品化）

> 工具=novel_event（op=append/read）；文件=book_dir/editorial/events-tape.jsonl。与 events.jsonl 分工：账本事件=发生了什么（工具自动记）；事件带=为什么+判了什么+还欠什么（编辑部口径）。

## 一、schema 与硬门

每行：`{ts, id(tNNN 自增), kind, ch?, what, why, ref?, actor, closes?, closes_thread?}`

- kind 七值：decision（决策）/verdict（判词）/revision（修订）/open_thread（欠线）/checkpoint（抗压缩检查点）/**hook（章末钩子，随 novel_chapter 的 hook 参数落）**/**payoff（兑现，闭线载体，必带 closes_thread）**
  - 后两类是 v7.10 并入的（钩子与欠线是同一条因果链的两端，生命周期一致，故共用埋下/兑现/闭线同一套对账）；hook/payoff 为**静默类**：只计数不占事件带窗口
- what/why 各 ≤60 字（工具硬门，防膨胀）；actor 必填
- open_thread 必带 closes（预期收线章，正整数）；闭线=closes_thread 引用欠线 id（工具对账防重复闭）
- verify 追欠线逾期（closes<当前章未闭→issue）

## 二、注入规则（保盲读红线）

| 角色 | 权限 |
|---|---|
| 主笔 | 工具面 deny（不能写事件带）；任务书内注"事件带摘要段"（主编从 read 结果手拼 ≤15 行，未闭欠线必含）——原写"写手"，v7.2 两座位制起"写手"即主笔的执笔职能 |
| 试读员/结构校准员/校对员 | **禁看**（盲读红线：判官不许知道编辑部意图） |
| 档案员 | 可 read（对账要记痕）。**粒度警告**：宿主侧 deny 只有**整工具**粒度、没有 op 级 ⇒ 保留 `novel_event` ＝把 `op=append` 一并给了它，靠纪律不放写（要硬面上只给读，只能改连接器侧） |
| 主编 | 全权；**压缩触发前 checkpoint 落带**（当轮推理摘要——文件不被压缩吃掉=抗压缩记忆） |

## 三、read 有界窗口

近 12 条非粘性全量 + **open_thread/checkpoint 永不摘要、始终全量留窗**（安全阀 40）+ 更早按 kind 计数 + 未闭欠线清单。硬上限 ~4K token。

## 四、批级断点续跑（checkpoint 的第二职能）

中断恢复 SOP：查 status.json 最后已定稿章 → novel_event read 带尾 → 主编重建调度位 → 从下一章 outline 起。断供/无头收束事故皆有前科，长批必须可续。

## 五、纪律

- 落带三类必记：每章 decision（why 必填）；verdict/revision 随状态流转；自设欠线 open_thread。
- 带子不撕页（append-only）；写错的 correction 用新条目说"更正 tNNN"。
- 每周 audit 抽检信噪比（Owner 历史教训：92% 噪音账本前科）——只记决策/判词/欠线三类，闲话不入带。
